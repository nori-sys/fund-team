# accepted判定条件仕様案 v1

状態：0310追加検証の仕様案。正式実装・本番採用の決定ではない。根拠は0310正式指示、1332のPhase 1～4最終適合版、Phase 5最終独立監査、固定入力の追補v4・分類v3・ゲートv4、取得済み2025年版公式taxonomy照合記録に限定する。入力、処理及び評価案の版は非公開の`0310_core8_evaluation_v1.json`で固定する。

## 判定の単位と順序

1. 固定8セルの対象企業、指標、2025年提出書類内の2024年3月期比較値／2025年3月期当期値、要求context次元署名を追補v4で固定する。対象外の候補はセル相対`rejected`とし、元factの全体状態には波及させない。
2. 候補factの出典書類・位置、concept QName、公式taxonomyでの定義、context/period、必要なdimension/member、value・unit・nil・符号、訂正関係を証拠ごとに照合する。概念名や値の一致、候補順、書類の新しさだけを採用根拠にしない。
3. 公式書類の表示・定義関係から、対象指標、会計基準・連結／単体の比較系列、当期／比較期の役割を結び、同一セルの重複factと訂正前後の採用出典を一意に解決する。出典の意味又は優先関係が未確認なら`hold`にする。
4. 候補の**全体判定**と**セル相対判定**の双方が根拠付き`accepted`で、セル内の採用候補が一意である場合に限り、当該セルの採用値とする。片側だけ`accepted`、他候補との競合、nil・unit・符号の未解決、再現不能があれば返さない。
5. 入力版、処理版、公式根拠、候補集合、評価版を記録する。同一入力・同一処理版で同じ評価案を得られることを確認する。新評価は別版に追記し、1332の元状態を変更しない。

`hold`は候補が存在しても採用証拠が不足する状態、セル相対`rejected`はそのセルの要求署名から外れることが確認された状態である。セル相対`rejected`をfact自体の無効認定にしない。採用系検索へ`hold`又は`rejected`を渡さない。
