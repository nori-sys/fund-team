## 取得・正規化の候補（未採用）

EDINET API Version 2の書類一覧・書類取得を入口候補とし、書類ID、EDINETコード、提出日時、様式コードおよび取得時点をメタデータとして扱う。書類由来のXBRL/CSV/PDF等は将来の候補形式であり、本作業では取得していない。XBRLを用いる場合も、連結/単体、会計基準、対象期間、単位、タクソノミ版を明示してから正規化する。

訂正は「元書類を消す」処理にしない。書類ID・訂正フラグ・訂正先/元書類参照・観測時刻を保持し、同一の企業、会計期間、指標、連結範囲、予想/実績区分について、公式の訂正関係を確認できる最新訂正版を利用候補とする。確認不能時は競合状態として採用せず保留する。

## PoC状態

**停止（未実施）**。理由は、APIキー発行にログイン認証が必要であり、承認範囲が既存認証の確認・使用、新規登録、認証情報の表示・共有、新規設定を禁止しているためである。実データ、原文、数値、書類IDの取得・保存はしていない。

再開には、Noriによる利用条件・認証方式・保存範囲・公開可否の判断、および対象、取得件数、保存先、DB変更権限を明記した別の承認済み指示が必要である。

EDINETは法定開示、機械可読形式、書類IDと訂正関係を利用できる可能性から、確定財務・長期履歴の**主系統候補**とする。ただし正式採用ではない。
