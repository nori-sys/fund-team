# バックアップ・復旧手順 v1（設計だけ）
旧DB/価格Gateway/既存backup/logs/FChart原本には接続・複製・復旧しない。新専用DBだけを対象に、非公開配置台帳の新バックアップ先と対象版を別承認する。

バックアップ：Nori承認範囲確認→reader未稼働/更新停止確認→原DB/全親実体・ACL・Git/sidecar不存在確認→共有読取ハンドルで更新拒否→入力DB SHA/size/FK/integrity/4対象32判定候補4と版確認→新規排他的なバックアップ名へ保存→SHA/size一致→独立した記録。既存名は上書きしない。停止プロセス操作やACL変更を黙示に含めない。

復旧：失敗資産を削除せず保全し、reader未稼働を維持する。Noriへ対象資産版/SHA・復旧元/新規復旧先・必要配置/権限・変更効果・影響範囲を提示し、対象を特定した別途復旧承認と正式指示を得る。新規名への排他的復旧だけを計画し、既存DB上書き・自動切戻し・単純削除をしない。配備先/config切替・ACL・プロセス停止も必要なら別操作として承認を得る。

復旧ゲート：許可版/コピー前後SHA一致、再解析/sidecarなし、FK/integrity、同じ4対象/32判定/候補/根拠/版、Reader契約、旧資産非干渉、カン開始前/完了独立監査、Noriの新たな内部稼働承認。現在はいずれも本番現物未作成につき未実施。リハーサルも今回行わない。
