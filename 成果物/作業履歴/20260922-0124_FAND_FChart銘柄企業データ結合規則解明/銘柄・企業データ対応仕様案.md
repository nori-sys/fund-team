# 銘柄・企業データ対応仕様案

対応する正式作業指示書：`作業指示/20260922-0124_FAND_FChart銘柄企業データ結合規則解明_作業指示書.md`

## 位置付け

これは読取り専用調査から得た暫定の対応仕様案である。企業同一性、財務項目、単位、倍率又は `Zaimu.dat` の結合を正式仕様として確定しない。

## 適用規則

1. `kabu.lst` 又は `Userkabu.ini` の第1列を銘柄コード、第2列を銘柄名称として扱う。この二つは現行4,289行で一致した。
2. `Userkabu.ini` 第4列を `p` とする。
3. `1 <= p <= 14297` の場合だけ、次の**候補座標**対応を使用できる。この対応は企業同一性を保証しない。

```text
銘柄コード・名称
  → Userkabu.ini 第4列 p（1始まり）
  → kigyo.dat  : 候補 byte [(p-1) * 823, p * 823)
  → kigyo2.dat : 候補 byte [(p-1) * 330, p * 330)
  → kigyo3.dat : 候補 byte [(p-1) * 330, p * 330)
```

4. `p = 0` の場合は「企業3ファイルへの座標未確認」とし、代替キーを推測しない。
5. `Zaimu.dat` は上記規則の対象外とする。レコード境界とキーが未確定のため、`p` をオフセット・行番号・レコード番号へ変換してはならない。

## 検証済み範囲

| 項目 | 結果 |
| --- | --- |
| 有効座標数 | 4,240 |
| 座標重複 | 0 |
| 座標範囲 | 1〜14,185（全て企業3ファイルの14,297レコード範囲内） |
| 座標未確認 | 49（第4列0） |
| 企業3ファイルの座標長 | `kigyo.dat`: 823 byte、`kigyo2.dat`/`kigyo3.dat`: 330 byte |

## 採用しない規則

- `kigyo.dat` の先頭4 byteと銘柄コードの一致だけによる結合
- `kabu.lst` の行番号と企業DATの行番号の直接結合
- 銘柄名称の任意バイト検索による結合
- 旧版DATの同一行又は完全一致だけによる現行企業同一性の確定
- `Zaimu.dat` への同一座標の仮定

## 利用制約

この仕様案は、企業3ファイルを読むための候補座標を再現するだけであり、企業同一性を保証する正式キーではない。正式DB、Data Gateway、Console、設定又は実装コードに利用してはならない。

公開区分は未明記のため、本仕様案をPublic GitHubへ送信しない。
