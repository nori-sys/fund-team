# キー構造初期検証

## 確認済み

3ファイルを同じ行番号で各14,297レコードとして読取り集計した。

| 比較 | 先頭4 byte一致 | 不一致 |
| --- | ---: | ---: |
| `kigyo.dat` と `kigyo2.dat` | 174 | 14,123 |
| `kigyo.dat` と `kigyo3.dat` | 174 | 14,123 |
| `kigyo2.dat` と `kigyo3.dat` | 13,079 | 1,218 |

`kigyo.dat` の先頭4 byteはユニーク6,099値、重複値851種、重複に属するレコード9,049件である。`kigyo2.dat` と `kigyo3.dat` の先頭4 byteはそれぞれユニーク14値・42値にとどまる。したがって、この領域を3ファイル共通の銘柄キーとみなす根拠はない。

重複する `kigyo.dat` 候補値（例: little-endian整数4445、4931、7678等）のレコードを比較すると、offset 37、112、167、222、277、332など、55 byte間隔の反復領域を含む複数領域に差分がある。値ゼロの重複には全バイト一致する組合せもある。

## 有力

- `kigyo.dat`、`kigyo2.dat`、`kigyo3.dat` は同一行数の固定長配列であり、行番号は候補結合軸である。
- `kigyo2.dat` と `kigyo3.dat` は先頭4 byteが約91.5%一致し、共通の区分・状態領域を持つ可能性がある。
- `kigyo.dat` の重複候補値には、55 byte反復領域の差分が伴う例があり、複数期・複数区分等を保持する可能性がある。

## 未確定

先頭4 byteの意味、重複理由、反復領域の項目名、行番号結合が実際に同一企業を表すか、候補コードと補助キーによる結合規則はいずれも未確定である。市場・時系列・銘柄履歴その他の理由は証拠不足のため確定しない。

`kabu.lst` との行番号結合は不成立として扱い、コード一致、企業名および補助領域の検証を継続する。
