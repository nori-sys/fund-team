# 代表銘柄候補再検証

## 確認済み

現行 `kigyo.dat` の先頭4 byteを符号なしリトルエンディアン整数として読取り、代表コードを探索した。

| 候補値 | レコード数 | レコード番号 |
| ---: | ---: | --- |
| 1001 | 1 | 0 |
| 1010 | 1 | 1 |
| 7203 | 0 | - |
| 6506 | 0 | - |
| 8267 | 0 | - |
| 2802 | 0 | - |
| 4755 | 0 | - |
| 9984 | 1 | 8758 |
| 1308 | 0 | - |

1001・1010のレコードには4桁・6桁のASCII数字候補が反復するが、企業名、業種、既知業績値を同一レコードから確認できなかった。9984の候補レコードも同様に企業同一性を確認する補助情報を得られていない。対応する `kigyo2.dat`・`kigyo3.dat` の同じ行の先頭16 byteは、上記3レコードで全てゼロだった。

## 有力

1001・1010は現行 `kabu.lst` にもある値で、現行 `kigyo.dat` の先頭2レコードに一度ずつ現れる。しかし、名称・業種・既知表示値によるクロスチェックが欠けるため、企業同一性の高確度確認には至らない。

## 未確定

先頭4 byte候補値と銘柄コードの関係、7203等が先頭4 byteに現れない理由、9984候補の企業同一性、行番号による3ファイル結合、財務項目の意味は未確定である。FChart画面の既知業績値は今回利用可能な証跡がないため、照合していない。

従って、現時点で複数企業に再現する高確度な対応規則は得られていない。候補コードだけを根拠に `kabu.lst` と結合しない。
