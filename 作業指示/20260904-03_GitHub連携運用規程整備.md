作業ID: 20260904-03  
対象プロジェクト: ファンドチーム  
発行者: ChatGPT（チャット）  
最終承認者: Nori  
目的: ChatGPT ↔ GitHub ↔ Codex の双方向連携を正式運用へ移行するため、現行規程と矛盾しない規程改定案を作成する。

## 01）前提

Nori承認済みの基本方針は次のとおり。

- ローカルWorkspaceを、実装・規程・重要資産の正本とする。
- GitHubは、作業指示・成果物・差分・レビューの共有／履歴管理層として使用する。
- GitHubをローカル正本の代替とはしない。
- 原則として、1 ChatGPTプロジェクト = 1 GitHubリポジトリ = 1 Codex Workspace の対応を採用する方向で整備する。
- 今回の作業では、まず規程案と必要変更案を作成し、未確認の正式文書を推測で上書きしない。

## 04）今回の作業範囲

今回は正式規程を直接上書きせず、現行文書を確認したうえで以下の「改定案」を作成する。

### A. 新規WORKFLOW案

`規程/WORKFLOW/GitHub連携運用.md`

最低限、以下を規定する。

- 目的と適用範囲
- ChatGPT / GitHub / Codex / Nori の役割分担
- 1プロジェクト1リポジトリ1Workspace対応の原則
- ローカルWorkspaceとGitHubの正本関係
- GitHubに置いてよい情報／置かない情報
- `作業指示/` と `成果物/` の用途
- ChatGPTがGitHubへ作成・更新してよい範囲
- CodexがGitHubへ作成・更新してよい範囲
- 受信・取得・レビューの基本フロー
- commit / push / fetch 等の基本原則
- Public / Private の扱い
- 認証情報・APIキー・token・秘密鍵・個人情報・機密情報の禁止事項
- force push、履歴改変、remote変更、認証方式変更等の承認境界
- GitHubとローカルの不一致時の扱い
- 停止条件
- 監査・記録
- 障害時の復旧方針

### B. `START_HERE.md` 最小変更案

GitHub連携を利用する場合に `規程/WORKFLOW/GitHub連携運用.md` を参照する入口を追加する。

既存の開始順序、正規場所停止ゲート、承認済み作業指示の優先順位を崩さない。

### C. `AGENTS.md` 最小変更案

現在の外部共有・AI間通信・権限原則を維持したまま、

「Nori承認済みの `GitHub連携運用.md` と承認済み個別作業指示に明記された範囲では、GitHubを共有／履歴管理層として使用できる」

という正式な許可経路を追加する案を作成する。

ただし、次は引き続き個別承認対象とする方向で設計する。

- 新規remoteの追加・変更・削除
- Git設定の恒久変更
- 認証方式変更
- credential / token / SSH key 等の設定・表示
- force push / 履歴改変
- リポジトリ公開範囲の変更
- 新規リポジトリ作成
- 機密情報の外部共有
- 規程・ROLE・重要資産のGitHub正本化

### D. その他の重要管理文書への影響確認

`プロジェクト運用方針.md`、`現行仕様書.md`、`変更履歴.md` の内容を確認し、今回の正式運用導入によって変更が必要かを判断する。

必要な場合は変更案を作成する。不要な場合は「変更不要」と根拠を示す。

## 05）重要な設計原則

### 正本

原則案:

- ローカルWorkspace: 実装、規程、重要資産の正本
- GitHub: 作業指示、成果物、差分、レビュー、受け渡し、履歴管理層

ただし、現行正式文書に異なる定義がある場合は、勝手に上書きせず不一致として報告する。

### GitHubへ置かないもの

最低限、以下はGitHubへ載せない方向で設計する。

- FChart原本
- 大容量株価データ
- SQLite本体（別途正式承認がある場合を除く）
- パスワード
- APIキー
- access token
- 秘密鍵
- 認証コード
- 個人情報
- その他の機密情報

### Publicリポジトリ

現行 `nori-sys/fund-team` はPublicであるため、GitHubへ書く内容は「公開されても問題のない情報」に限定する設計とする。

正式運用でPrivateを原則とするべきか、Publicを許容するかは、現行文書・実運用を確認して提案する。推測で公開範囲を変更しない。

## 07）レビュー観点

提出前に以下を確認する。

- 現行規程と矛盾していないか
- 同じ情報を複数箇所で正式管理する設計になっていないか
- GitHubがローカル正本を置き換える設計になっていないか
- ChatGPTとCodexの権限が過大になっていないか
- 外部共有の承認境界が曖昧でないか
- Publicリポジトリへの機密情報流出リスクを抑えているか
- 既存の正規場所停止ゲートを弱めていないか
- 既存の資産保全規則を弱めていないか
- 不可逆操作を自動化していないか
- 誤送信・誤プロジェクト混入時の停止条件があるか
