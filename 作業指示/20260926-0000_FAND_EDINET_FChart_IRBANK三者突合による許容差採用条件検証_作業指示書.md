## 04）比較規則案

### A. 比較可能性を先に判定する

EDINET候補と比較源の双方で、企業同一性、指標定義、会計期間・当期/比較期、連結/単体、会計基準、訂正前後、値の符号、単位・倍率、表示精度、出典・版が証跡付きで対応する場合だけ数値を比較する。通貨・単位の換算は両方の公表単位と換算倍率を確証でき、十進数で正規化できる場合に限る。意味的不一致を近似値として扱わない。不明ならcomparison_hold、確定した意味的不一致はmismatchに理由を添える。

### B. 数値計算

比較可能と確定した金額に限り、EDINET表示値Eを固定の分母、比較源の表示値Xを比較値とする。公表単位へ正規化後、十進数の厳密演算で d = |X−E| / |E| を計算する。d ≤ 0.005を閾値内とし、境界値は含める。浮動小数点で再計算せず、比較前の任意丸め、閾値の緩和、源ごとの分母変更をしない。表示丸めは分類後に限り、入力値・倍率・表示精度・計算版を非公開記録に残す。

E＝0は相対差を計算せずcomparison_holdとする。正規化後の表示最小単位の半分を各源の丸め幅qE、qXとし、大きい方をqとする。|E| ≤ q / 0.005を0近傍としてcomparison_holdとする。表示精度が不明なら同様にcomparison_hold。丸め区間の不確かさは分子にのみ適用し、分母は表示値|E|に固定する。Dmin＝max(0, |X−E|−qE−qX)、Dmax＝|X−E|＋qE＋qX、dmin＝Dmin/|E|、dmax＝Dmax/|E| と定義する。dmin ≤ 0.005 ＜ dmax の境界跨ぎはcomparison_holdとする。dmax ≤ 0.005だけを確実な閾値内、dmin ＞ 0.005だけを確実な閾値超過とする。0近傍判定が先なので分母ゼロ・丸め区間のゼロ跨ぎを計算に持ち込まない。式・入力精度・版を記録し再計算可能にする。

両方が非零で符号が反対なら、意味対応が確定している場合はmismatch、符号規約が未確認ならcomparison_holdとする。同符号かつ意味対応・精度条件を満たす場合、正規化後の表示値が厳密に等しくdmax ≤ 0.005ならexact_match、表示値は異なるがdmax ≤ 0.005ならtolerance_match、dmin ＞ 0.005ならmismatch、残りの境界跨ぎはcomparison_holdとする。表示値が等しくても丸め幅のため境界を確定できなければcomparison_holdとする。exact_matchは公表表示値の一致であり公式factの同一性ではない。

### C. 三者の関係

EDINET対FChart、EDINET対IRBANKを別々に分類し、三者の値が揃い比較可能な場合だけFChart対IRBANKの整合も記録する。FChart対IRBANKの相互差も分母は固定した|E|、丸め幅は両比較源の和を用いて04）Bと同じ式で判定する。片方の欠損、未確認、意味的不一致又は両源の結果衝突を隠さず、多数決はしない。

三者総合評価は次の順に最初に該当した1区分を付ける。第一に、いずれかの源の版・権利・意味対応が未確認ならunverified。第二に、未確認はないがいずれかの源に値が無ければunavailable。第三に、両源が利用可能で、いずれかのEDINET対比較源又は両比較源間に確定したmismatchがあればconflict。第四に、両源が利用可能でmismatchはないが、いずれかの比較がcomparison_holdならpartial。第五に、3組すべてがexact_match又はtolerance_matchならthree_source_consistentとする。上位区分でも各組の結果・欠損・衝突理由を消さない。この5条件のどれにも入らない異常入力は分類せず停止して規則を再監査する。三者総合評価は0310のacceptedを変更しない。
