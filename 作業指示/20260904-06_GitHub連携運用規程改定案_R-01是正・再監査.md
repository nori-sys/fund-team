## 01）前提

監査指摘 R-01:

> GitHub操作の承認経路が変更案間で一致していない。新規 `GitHub連携運用.md` 案は「承認済み個別作業指示またはNoriの明示指示」を許容する一方、他の変更案は個別作業指示を必須と読める。

Nori承認済みの是正方針は次のとおり。

### 読取り

GitHub上の情報の読取り・確認は、以下のいずれかを根拠として実施できる方向で統一する。

- Noriの明示的な直接指示
- 承認済みの `GitHub連携運用.md` に定められた定常的な参照運用
- 承認済み個別作業指示

ただし、認証情報、個人情報、機密情報、承認範囲外の外部情報を取得・表示・保存してはならない。

### 書込み

GitHubへの作成・更新・commit・push等の書込み操作は、原則として **Nori承認済みの個別作業指示に、対象・範囲・保存先・禁止事項・完了条件が明記されている場合だけ実施可能** とする方向で統一する。

### 特別承認が必要な操作

次は個別作業指示に含まれていても、別途Noriの明示承認を必要とする方向で統一する。

- 新規remoteの追加・変更・削除
- Git設定の恒久変更
- 認証方式の変更
- credential / access token / API key / SSH key 等の設定・表示・共有
- force push
- rebase等による既存共有履歴の実質的改変
- branch protection / repository ruleset の変更
- リポジトリのPublic / Private変更
- 新規リポジトリ作成・削除
- 機密情報・個人情報・重要資産の外部共有
- 規程、ROLE、重要資産のGitHub正本化

## 06）承認経路の統一要件

改定案全体で、最低限次を明確かつ矛盾なく表現する。

### A. 読取り・確認

- GitHub上の承認済み文書・作業指示・成果物等の読取りは、Noriの明示指示、承認済みGitHub連携運用、または承認済み個別作業指示を根拠に実施可能。
- 読取りは、それ自体でローカルWorkspace変更、Git設定変更、外部書込み、正式承認、運用開始を意味しない。

### B. 書込み

- GitHubへの新規作成、更新、commit、push等は、承認済み個別作業指示に明記された範囲だけ実施可能。
- 「GitHub連携運用.md」が存在することだけを根拠に、任意の書込み権限を常設しない。

### C. 高リスク操作

- remote変更、認証変更、force push、履歴改変、公開範囲変更、新規リポジトリ作成等は、個別作業指示に加え、Noriの明示承認が必要。

### D. 正本

- ローカルWorkspaceの承認済み規程・重要資産を正本とする。
- GitHub上の規程はChatGPT等からの参照用ミラーであり、ローカル正本を自動的に置換しない。
- GitHubミラーとローカル正本が不一致の場合、GitHub側を推測で正本扱いせず停止・報告する。
