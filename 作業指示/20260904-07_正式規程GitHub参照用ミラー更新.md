## 2. 目的

ローカルWorkspaceで正式発行済みの規程4文書を、内容を変更せず `nori-sys/fund-team` のGitHub参照用ミラーへ反映し、ChatGPTが最新の正式規程を参照できる状態にする。

GitHubは参照用ミラーであり、ローカルWorkspace上の正式規程・実装・重要資産の正本を置き換えない。

## 3. 正規作業場所

作業開始時および書込み直前に、次の正規作業場所とGitルートの一致を確認する。

`E:\AI ワークスペース\CODEX\ファンドチーム_Workspace`

確認例:

```powershell
Get-Location
git rev-parse --show-toplevel
```

不一致、未確認、確認不能の場合は書込みを行わず停止し、Noriへ報告する。

## 4. 正式な参照根拠

本作業では、ローカルWorkspace上で正式発行済みの次の文書と、本作業指示書を実行根拠とする。

- `AGENTS.md`
- `START_HERE.md`
- `規程/WORKFLOW/GitHub連携運用.md`
- `規程/WORKFLOW/AI間通信運用.md`
- 本作業指示書 `20260904-07`

過去のレビュー案、監査前案、過去成果物は正式規程を上書きしない。

## 5. ミラー更新対象

GitHub参照用ミラーへ反映する対象は、次の4文書だけとする。

1. `AGENTS.md`
2. `START_HERE.md`
3. `規程/WORKFLOW/GitHub連携運用.md`
4. `規程/WORKFLOW/AI間通信運用.md`

既存の `AGENTS.md`、`START_HERE.md`、`AI間通信運用.md` は、ローカル正式版との差分を確認したうえで更新する。

`規程/WORKFLOW/GitHub連携運用.md` は、GitHub側に存在しない場合は新規追加する。

## 6. 実施条件

1. 作業開始時および各書込み直前に正規WorkspaceとGitルートを確認する。
2. ローカル側の対象4文書が正式発行済みであることを確認する。
3. GitHub側は参照用ミラーとして扱い、正本化しない。
4. ミラーへ反映する本文は、ローカル正式版から要約、補完、再解釈、意図的整形変更を行わない。
5. 既存GitHubミラーとの内容差分を確認し、ローカル正式版を基準に更新する。
6. 対象リポジトリ、remote、branch、既存未commit変更、stage対象を確認する。
7. 対象4文書以外の既存変更を安全に分離できない場合は停止する。
8. 資格情報、個人情報、機密情報その他Publicリポジトリへ公開すべきでない情報が含まれていないことを確認する。
9. stage、commit、push対象を対象4文書だけに限定する。
10. 通常の非破壊的commit・pushだけを使用する。

## 7. 禁止事項

次を行ってはならない。

- ローカル正式規程本文の変更
- ROLE文書の変更
- 対象4文書以外の作成、更新、移動、改名、削除
- GitHubを正式規程の正本として扱うこと
- force push
- rebase等による既存共有履歴の実質的改変
- remoteの追加、変更、削除
- Git設定の恒久変更
- 認証方式、credential、access token、API key、SSH key等の設定、表示、共有
- Public / Private設定変更
- repository ruleset、branch protectionその他GitHub設定変更
- 新規リポジトリ作成または削除
- 自動同期、Webhook、GitHub Actions、Codex自動起動その他の自動化導入
- 対象外の未commit変更をcommitへ混入させること

上記の高リスク操作が必要になった場合は実施せず停止し、Noriへ報告する。

## 8. 安全確認

commit・push前に少なくとも次を確認する。

- 対象ファイルが4文書だけである
- ローカル正式版との内容一致
- GitHub公開不可情報が含まれない
- 資格情報形式が検出されない
- 既存未commit変更が混入していない
- 対象branchが意図したbranchである
- remoteが意図した `nori-sys/fund-team` である

疑義がある場合は推測で継続しない。

2. GitHubミラーとローカル正式版の内容一致を確認する。
3. 対象4文書以外が変更されていないことを確認する。
4. 正常なcommit・pushが完了している。
5. commit SHAを取得している。
6. 公開安全性確認結果を記録している。
7. 未解決事項、未確認事項または残存リスクがあれば明記している。

## 11. 最終原則

本作業の目的は、正式規程の正本をGitHubへ移すことではなく、ローカル正式規程をChatGPTが安全に参照できるGitHubミラーへ同期することである。

承認範囲を超える変更、高リスク操作、機密情報の外部共有、正本性の変更は行わない。
