# 監査運用

## 目的と原則

Noriが監査またはレビューを明示した書類を、独立レビュー、是正、再監査、正式発行承認の順に扱う。未承認案を正式文書として扱わない。

`ROLE_FUND_カン_監査` の適用状態およびNoriによる監査担当指定を確認できる場合だけ、カンは監査を開始する。いずれかを確認できない場合は、監査を開始せず、`監査不能` と必要なNori判断事項を報告する。

## 手順

1. 主担当AIが、対象、目的、監査観点、禁止事項、成果物、保存先、停止条件を定めた完全な案を作成する。
2. 独立したカンが、適合（承認可）、要修正または監査不能を根拠とともに報告する。カンは起案、実装又は是正を行わない。
3. Noriの依頼範囲および既存の承認済み作業指示を変更・拡張しない是正だけを主担当AIが行い、再監査する。Nori判断事項に依存する是正・再監査は停止し、判断を推測、代替又は回避して進めない。判断事項から独立する是正は継続できる。
4. 適合（承認可）後、主担当AIは完全な案をNoriへ提示する。
5. Noriが正式発行を明示承認した場合だけ、指定のファイル・フォルダを作成・更新し、実在・サイズ・内容を確認する。

適合（承認可）は発行推奨であり、フォルダ作成、運用開始、通信、会話DB実施、DB変更、外部共有または全体完了を承認しない。既存の保全対象と会話DB導入指示は監査対象外として保全する。

## 停止条件

対象、承認状態、権限、根拠または保存先が不明確な場合、監査担当の独立性を確保できない場合、または正規作業場所の確認に失敗した場合は、発行または更新を停止してNoriへ報告する。
