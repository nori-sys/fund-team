# GitHub連携運用

## 目的

ファンドチームにおけるGitHub利用を、作業指示、成果物、差分、レビュー、受け渡し及び履歴管理の共有・参照用ミラー層として、安全かつ追跡可能に扱う。GitHubはローカルWorkspaceの規程、実装又は重要資産の正本を置き換えない。

## 適用範囲

本運用は、Noriが承認した `1 ChatGPTプロジェクト = 1 GitHubリポジトリ = 1 Codex Workspace` の対応に限り適用する。本運用は自動同期、Webhook、GitHub Actions、Codex自動起動、会話DB、認証情報管理又はPublic/Private方針の決定を導入しない。

`ChatGPT/CURRENT_CONTEXT.md` 及び `ChatGPT/HANDOVER/` は、承認済みのスレッド引継ぎ運用として扱う。`ChatGPT/作業指示案/` は、ChatGPTが作成するCodex向け未承認作業指示案の保管・更新に限定する。`ChatGPT/規程案/` は、ChatGPTが作成する未承認の規程案、ROLE案、WORKFLOW案及び入口文書案の保管・更新に限定する。いずれも、保存又はGitHub上の存在だけで承認、正式発行、送達、受領又は実行開始を意味しない。これらの保存先は正式規程、ROLE、WORKFLOW又は正式成果物の保存場所ではなく、これらの変更権限又はCodexの実行根拠を与えない。

## 正本と参照用ミラー

1. ローカルWorkspaceの承認済み規程、実装及び重要資産を正本とする。
2. GitHub上の `AGENTS.md`、`START_HERE.md`、`規程/` は、ChatGPT等が必要な現行規程を参照するための参照用ミラーであり、正本ではない。
3. GitHubからローカル規程を無条件に取得、上書き又は反映してはならない。
4. ローカル正本とミラーの内容、版、承認状態又は対象リポジトリに不一致がある場合、自動修正せず停止し、差分と影響をNoriへ報告する。

## 役割

| 主体 | 役割と制約 |
| --- | --- |
| Nori | 正本性、公開条件、個別GitHub操作、正式発行及び運用開始の最終判断者 |
| ChatGPT | 以下の承認経路に従い、GitHub上の参照用ミラー、作業指示又は公開可能なレビュー情報を参照又は作成する。GitHub内容だけでローカル作業の承認又は実施を確定しない。 |
| Codex | 正規WorkspaceとGitルートを確認し、以下の承認経路に従い成果物作成、差分確認、commit又はpushを実施する。既存ROLE及び個別指示を超えて権限を拡張しない。 |
| GitHub | 公開可能な情報の共有、履歴及び参照用ミラー層。正本、承認者又は自動実行基盤ではない。 |

## GitHub操作の承認経路

### 読取り・確認

GitHub上の承認済み文書、作業指示、成果物、差分又はcommit情報の読取り・確認は、次のいずれかを根拠として実施できる。

1. Noriの明示的な直接指示
2. 承認済み `GitHub連携運用.md` に定める定常的な参照運用
3. 承認済み個別作業指示

読取り・確認は、それ自体でローカルWorkspace変更、Git設定変更、外部書込み、正式承認、送達、受領、実行又は運用開始を意味しない。認証情報、個人情報、機密情報又は承認範囲外の外部情報を取得、表示又は保存してはならない。

### 書込み

GitHubへの書込みは、Noriの明示的な直接指示、承認済みWORKFLOWに定める定常運用又はNori承認済み個別作業指示を根拠として実施できる。定常書込みは、目的、対象、保存先、禁止事項、成果物、完了条件及びNori承認済みの公開区分を定める個別作業指示に付随する処理に限る。ただし、`ChatGPT/作業指示案/` 又は `ChatGPT/規程案/` の未承認案の作成・更新は、Nori承認済みの公開区分・許可パス、公開安全性照合、commit記録及び疑義時停止を満たす独立した定常例外とし、個別作業指示を要しない。承認後の正式文書ミラー更新は、ローカル正本の正式発行についてNoriが明示承認し、公開条件を満たす対象だけを根拠として実施できる。Noriの直接指示又は本運用の存在だけを根拠に、任意の書込み権限を常設しない。

定常書込みの対象は、承認済み `nori-sys/fund-team` リポジトリの `origin/main` における、個別作業指示で `公開可` とされた作業指示、作業履歴内の作業報告書・独立監査結果・検証結果・作業固有成果物、承認後の正式文書の参照用ミラー、又は `ChatGPT/作業指示案/`・`ChatGPT/規程案/` の公開可能な未承認案に限る。正式DB、コード、設定、規程、ROLE、WORKFLOWその他の既定配置先を持つ資産は、作業履歴へ複製して定常書込みの対象にしない。

書込み前に、正規Workspace、Gitルート、対象リポジトリ、remote、branch、remote最新状態の取得・確認、ローカルbranchとremote branchの先行・遅延・分岐、既存未commit変更、未追跡ファイル、stage対象、公開安全性及び個別指示との一致を確認する。公開区分はNoriが `公開可` と判断した対象だけとし、担当AIは機密情報・個人情報・禁止資産・個別禁止との照合結果を原報告に記録する。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。ローカルmainとGitHub mainが常に一致すると仮定してはならない。既存変更を安全に分離できない場合は停止する。

既存未commit変更、未追跡ファイル又は別作業の変更があるWorkspaceでは、これらを安易な `pull`、`merge`、`rebase`、`reset` 又は `stash` で処理しない。定常手順では正規Workspaceの外にある一時worktreeを利用しない。Noriが対象worktreeを明示承認した個別例外では、worktree内で正本又は保全対象を更新せず、対象変更だけを安全に分離できる場合に限る。non-fast-forward、競合又は分岐を検知した場合は、対象変更だけを安全に分離できない限り無理に同期又は統合しない。force push、remote変更、Git設定変更又は認証方式変更が必要な場合は停止し、従来どおりNoriの明示承認を必要とする。

### 高リスク操作

次の操作は、承認済み個別作業指示に含まれていても、別途Noriの明示承認を必要とする。

- remoteの追加、変更又は削除
- Git設定の恒久変更
- 認証方式、credential、access token、API key又はSSH keyの設定、表示又は共有
- force push、rebase等による既存共有履歴の実質的改変
- branch protection又はrepository rulesetの変更
- リポジトリのPublic / Private変更
- 新規リポジトリ作成又は削除
- 機密情報、個人情報又は重要資産の外部共有
- 規程、ROLE又は重要資産のGitHub正本化

## GitHubへ置ける情報と置けない情報

公開可能と明確に判断できる作業指示、成果物、レビュー、差分、commit記録及び承認済み規程の参照用ミラーだけを置ける。現行 `nori-sys/fund-team` はPublicであるため、公開可否に疑義がある情報は置かない。

次をGitHubへ置いてはならない。

- パスワード、APIキー、access token、認証コード、SSH秘密鍵その他の認証情報
- 個人情報、顧客・取引先情報その他の機密情報
- FChart原本、大容量株価データ、`database/fund_stock.db`、バックアップDB、ログ原本
- 公開可否、正本性又は保存権限が未確定の資産

## 作業指示・成果物の扱い

- `作業指示/` は、Nori承認済みの実行範囲を示す文書を共有・参照する用途に限る。GitHub上の表示又は取得だけで、Nori承認、送達、受領、実施開始を自動的に意味しない。
- `成果物/` は、承認済み作業の公開可能な成果物又は原報告を共有する用途に限る。未承認案は正式規程として扱わない。
- GitHub経由で受信した内容は、対象リポジトリ、branch、commit、対象ファイル、承認状態及び公開安全性を確認するまで実行根拠にしない。

## 基本フロー

### ChatGPT → GitHub → Codex

1. ChatGPTは、承認済み `nori-sys/fund-team` の `origin/main` におけるNori承認済み公開区分・許可パスだけへ、公開可能な `ChatGPT/作業指示案/` 又は `ChatGPT/規程案/` の未承認案を作成又は更新できる。送信前に機密情報・個人情報・禁止資産・個別禁止との照合を行い、commit記録に対象パス、公開区分及び照合結果を残す。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。
2. Codexは、読取り・確認については本運用の承認経路に従い、正規Workspace、Gitルート、対象repo・remote・branch・commit・パス及び内容を確認する。
3. Codexは、対象ファイルだけをローカルWorkspaceの同一パスへ限定取得できる。ローカル同名ファイルがある場合は、内容ハッシュと差分を確認し、不一致なら上書き・取得をせずNoriへ報告する。Noriが明示した置換以外は、Workspace全体の無条件な `git pull`、merge、rebase、reset又は上書き同期を定常処理としない。
4. Codexは、ローカル正本と承認済み個別指示に矛盾しない場合だけ着手する。不一致、認証要求、公開安全性の疑義又は対象外変更を検知した場合は停止する。

### Codex → GitHub → ChatGPT

1. Codexは、目的、対象、保存先、禁止事項、成果物、完了条件及びNori承認済みの公開区分を定める個別作業指示に基づく作業について、作業完了又は監査完了を待たず、作業履歴内に保存された `公開可` の途中作業報告書、独立監査結果、検証結果及び当該作業固有成果物だけを同一パスへ反映できる。反映対象は、公開安全性確認を完了し、「反映は作業完了・監査完了・Nori承認・正式成果物受領を意味しない」ことを明記したものに限る。
2. commit前に、stage対象が承認済みの公開可ファイルだけであること、機密情報及び禁止対象が含まれないこと、既存未commit変更・未追跡ファイル・別作業資産が混入しないことを確認する。公開可否に疑義、未分類又は個別禁止がある場合は送信しない。
3. 通常のcommit・push後、commit ID、branch、remote、送信ファイル、対応する個別作業指示、公開区分、公開安全性照合、反映時点の作業状態、検証結果及び未解決事項を原報告する。反映時点の作業状態は事実として記録し、承認又は完了を推測で記録しない。
4. ChatGPTは、対象commitの公開可能な情報を直接読取り・確認し、評価、壁打ち又は次段階の作業指示案・規程案の改善に用いることができる。ただし、GitHub上の内容だけで承認、送達、受領、実施、作業全体の完了又は重要資産変更を自動認定しない。

### 規程ミラー更新

1. ローカル正本の正式発行後、Nori承認済み公開区分を満たす対象文書だけをミラー対象にする。
2. 更新前後に対象パス、内容、commit ID及び正本の承認根拠を確認する。
3. 不一致時は修正、pull、merge又は上書きを自動実行せず停止・報告する。

## AI間通信との関係

通常の逐次AI間通信の通信ID、Markdown正本及び状態管理は `AI間通信運用.md` に従う。本運用はGitHubを共有・履歴・参照用ミラー層として限定し、AI通信の正本、送達、受領又は承認を代替しない。

## Public / Private

Publicリポジトリでは、公開されても問題のない情報だけを扱う。Private化又はPublic許容範囲の標準方針は本運用では決定しない。公開可否が不明な場合は、Publicリポジトリに送信せずNoriへ判断を求める。

## 停止条件と障害時の復旧

正規Workspace、Gitルート、対象リポジトリ、remote、branch、承認状態又は公開安全性を確認できない場合は停止する。競合、認証要求、remote変更、履歴改変又は設定変更が必要な場合も停止する。

自動復旧、force push、reset、rebase又は認証設定変更は行わない。対象commit、remote応答、差分及び影響範囲を記録し、Noriの個別判断を待つ。ローカル正本又は保全対象の上書きによる解消を試みない。

## 監査と記録

正式規程への発行前は `監査運用.md` に従い、必要な独立監査、Noriレビュー及び明示承認を経る。承認済みGitHub操作は、対象、根拠、branch、commit ID、送信又は取得ファイル、公開区分、公開安全性照合、既存資産への非干渉確認、検証結果及び未解決事項を原報告に残す。
