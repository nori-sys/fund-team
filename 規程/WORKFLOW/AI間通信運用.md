# AI間通信運用

## 目的と範囲

FUNDの逐次AI間通信を、承認、担当、状態、保存先および証跡が追跡できるMarkdown記録として扱う。初期運用は単一作業の逐次通信だけとし、SQLite通信台帳、自動通知、常時監視、並行通信、外部共有および共有検索は対象外とする。

## 役割と開始条件

Noriが最終判断者である。バフェットは承認済み運用内で通信管理・記憶管理を担い、こう・カズは承認済み範囲の原報告を提出し、カンは独立監査報告だけを提出する。未承認の内容を指示・実行根拠にしない。Noriによる適用承認、ROLE、個別承認状態又は保存先を確認できない場合は、採番・送達・記録を停止する。

## 識別子・状態・証跡

通信IDは `FUND-AI-COMM-YYYYMMDD-NNN` とし、採番前に `連絡/AI通信/` の既存IDを確認して重複を避ける。記録には、通信ID、日時、送信者、受信者、種別、対象、要旨、状態、根拠、関連承認ID、関連通信ID、保存先、保存確認を必須とする。状態は `下書き / Nori承認済み / 送達済み / 受領済み / 着手中 / Nori確認待ち / 保留 / 差戻し / 取消 / 完了` とする。`Nori承認済み` はNoriの明示承認、`送達済み`・`受領済み` は実証済み事実、`着手中`・`完了` は担当AIの原報告に基づく当該作業状態だけを記録する。どの状態も権限拡張又は作業全体の完了を意味しない。

通信記録の正本は `連絡/AI通信/` のMarkdownとする。原報告は `成果物/` に別保存する。通信記録は、スレッド引継ぎ、記憶正本又は会話DBを代替しない。`保存済み` は実在かつ0バイトでないことの確認後だけ記録する。AI-COMMの存在は送達完了、受領、実施、承認または別プロジェクトへの引継ぎを自動的に意味しない。保存先が未存在又は不明な場合は新設・代替保存しない。

## 保全と停止

本運用は `database/fund_stock.db`、`database/backup/`、`logs/`、外部FChart原本、設定、実装コードおよび会話DBを変更しない。保存先、採番状況、承認状態または正規作業場所を確認できない場合は、採番・送達・記録を停止してNoriへ報告する。
