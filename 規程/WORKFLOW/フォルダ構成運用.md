# フォルダ構成運用

## 原則

同じ情報を複数の場所で正式管理しない。未承認案は規程に保存しない。作成・移動・改名・削除は正規作業場所確認とNoriの承認後だけ行い、削除は単純削除せず `削除候補/` へ退避する。退避時は対象、元の場所、理由、承認、日時および復元可能性を記録する。`ChatGPT/作業指示案/` 又は `ChatGPT/規程案/` への保存は、承認、正式発行、送達、受領又は実行開始を意味しない。

## フォルダの役割

| パス | 役割 | 正本・制約 |
| --- | --- | --- |
| `規程/WORKFLOW/` | 承認済みの反復運用 | 未承認案は置かない |
| `連絡/Inbox/` | 受信作業領域 | 通信記録の正本ではない |
| `連絡/Outbox/` | 送信作業領域・引き継ぎメモ | 通信記録の正本ではない |
| `連絡/AI通信/` | AI間通信のMarkdown正本 | 承認済みのAI間通信運用に基づくMarkdown正本。各記録は状態と根拠を明記し、未承認内容を実行根拠・正式決定・送達済みとして扱わない |
| `ChatGPT/作業指示案/` | ChatGPT作成の未承認Codex向け作業指示案の保管 | 未承認・未発行であり、Codexの正式な実行根拠ではない。Noriが正式承認した後だけ正式な `作業指示/` 運用へ移行する。正式規程、ROLE、WORKFLOW又は正式成果物は置かない |
| `ChatGPT/規程案/` | ChatGPT作成の未承認規程案・ROLE案・WORKFLOW案・入口文書案の保管 | 直下にはAGENTS改定案・START_HERE改定案、`ROLE/` にはROLE改定案、`WORKFLOW/` にはWORKFLOW改定案を置く。未承認であり、正式規程、正式ROLE、正式WORKFLOW又は正式入口文書ではない。GitHub又はローカルに存在するだけで正式承認・正式発行・実行根拠を意味しない |
| `記憶/` | 承認済み運用に基づく記憶正本・更新判定 | 正式規程を置かない |
| `削除候補/` | 承認済み削除候補の退避 | DB・原本・規程を無断移動しない |

`チャットDB/` は会話DBの個別作業指示で許可された対象だけを置く。既存の `database/`、`logs/`、`tools/`、`work/`、`作業指示/`、`成果物/`、`.agents/` と外部FChart原本は、この運用による新設・移動・変更の対象外とする。

`ChatGPT/規程案/` は `GitHub連携運用.md` に定める定常受け渡し対象とする。ChatGPTは、承認済みの `nori-sys/fund-team` リポジトリの `origin/main` におけるNori承認済み公開区分・許可パスだけへ、公開可能な未承認案を、個別作業指示を要しない限定的な定常例外として作成・更新できる。送信前に機密情報・個人情報・禁止資産・個別禁止との照合を行い、commit記録に対象パス、公開区分及び照合結果を残す。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。Codexは必要な対象ファイルだけをローカルWorkspaceの同一パスへ限定取得できる。取得前に対象repo・remote・branch・commit・パス、ローカル同名ファイルの有無・ハッシュ・差分を確認し、内容不一致時は上書きせず停止・Nori報告する。Workspace全体の無条件同期又はGitHub版による正式規程の上書きを行わない。`ChatGPT/規程案/` の作成・更新権限を正式規程・ROLE・WORKFLOWの変更権限へ拡張しない。

## 発行・運用開始の境界

フォルダ作成と運用開始は承認された対象・保存先の範囲だけで行い、会話DB実施は別の個別指示に従う。
