# フォルダ構成運用

## 原則

同じ情報を複数の場所で正式管理しない。未承認案は規程に保存しない。作成・移動・改名・削除は正規作業場所確認とNoriの承認後だけ行い、削除は単純削除せず `削除候補/` へ退避する。退避時は対象、元の場所、理由、承認、日時および復元可能性を記録する。`ChatGPT/作業指示案/` 又は `ChatGPT/規程案/` への保存は、承認、正式発行、送達、受領又は実行開始を意味しない。

`ChatGPT/運用/` に置く文書は、Noriが文書単位で承認した、ChatGPT自身の作業品質又は文書作成方法に関する内部的な運用基準に限る。各文書は、Noriの承認根拠、対象、適用範囲および状態を本文に明記する。フォルダ又は文書の存在だけで、承認、正式発行、送達、受領又はCodexの実行根拠とはならない。未承認案、正式規程案、ROLE案、WORKFLOW案又は個別作業指示を正式運用基準として配置してはならない。

## 非公開実データ隔離領域の事前照合

非公開実データを作成又は保存する隔離領域を使用する場合は、最初の実データ取得・書込み前に、承認済み個別作業指示の保存先と実際の場所を照合する。既存の正規作業場所ゲートを先に通過し、正規Workspace内を保存先とする場合は、確認済みのGitルートから相対パスを結合して対象パスを生成する。Workspace名や区切りを手入力で組み立てた文字列だけを根拠にしない。

指示書に記載された絶対パス、Noriの最新の明示指示、生成した対象パスについて、表示上の文字列に加え、親子関係、階層数及び各パス構成要素を照合する。バックスラッシュはWindowsのパス区切りとして扱い、アンダースコアの表示用文字とはみなさない。パスの正規化、存在確認又は同名末尾だけで、異なる階層を同一と判定しない。既存の親及び対象について実体と再解析ポイントの有無を確認する。対象が未作成の場合は、承認された親までを確認し、対象作成後に実体を再照合する。

隔離領域のアクセス権は、承認済み個別作業指示で定めた許可主体、権限及び継承方針と照合する。広い継承権限、不明な主体又は想定外の権限が残る場合は、非公開実データを書き込まない。Git管理下の非公開領域では、当該領域に限定したGit除外及び対象ファイルが追跡・stageされていないことを確認する。Git除外だけで強制追加まで防止できるとは扱わず、Gitへ追加・送信する前の対象パス確認も別に行う。ACL又はGit除外の変更は、確認作業に付随する黙示権限としない。

照合結果は、確認日時、承認根拠、対象、場所の一致、実体・再解析ポイント、ACL、Git状態及び未決事項を、公開区分に従って記録する。実識別子、抽出値、認証情報及び非公開ハッシュを公開用記録へ載せない。対象、保存先又は権限が不一致・未確認の場合、実データ取得・作成・移動及び隔離ゲート通過判定を停止し、Noriの判断を求める。正式指示と最新指示の不一致を担当AIが黙示修正しない。

## フォルダの役割

| パス | 役割 | 正本・制約 |
| --- | --- | --- |
| `規程/WORKFLOW/` | 承認済みの反復運用 | 未承認案は置かない |
| `連絡/Inbox/` | 受信作業領域 | 通信記録の正本ではない |
| `連絡/Outbox/` | 送信作業領域・引き継ぎメモ | 通信記録の正本ではない |
| `連絡/AI通信/` | AI間通信のMarkdown正本 | 承認済みのAI間通信運用に基づくMarkdown正本。各記録は状態と根拠を明記し、未承認内容を実行根拠・正式決定・送達済みとして扱わない |
| `ChatGPT/作業指示案/` | ChatGPT作成の未承認Codex向け作業指示案の保管 | 未承認・未発行であり、Codexの正式な実行根拠ではない。Noriが正式承認した後だけ正式な `作業指示/` 運用へ移行する。正式規程、ROLE、WORKFLOW又は正式成果物は置かない |
| `ChatGPT/規程案/` | ChatGPT作成の未承認規程案・ROLE案・WORKFLOW案・入口文書案の保管 | 直下にはAGENTS改定案・START_HERE改定案、`ROLE/` にはROLE改定案、`WORKFLOW/` にはWORKFLOW改定案を置く。未承認であり、正式規程、正式ROLE、正式WORKFLOW又は正式入口文書ではない。GitHub又はローカルに存在するだけで正式承認・正式発行・実行根拠を意味しない |
| `ChatGPT/運用/` | ChatGPT自身の作業品質・文書作成方法その他の、文書単位でNori承認済みの内部運用基準の保存 | ChatGPT側の内部基準に限定する。Codex又はファンドチームの行為を拘束せず、正式規程、ROLE、正式WORKFLOW、個別作業指示又はAI間通信の正本・保存場所・実行根拠・変更権限にはしない。未承認案は置かない |
| `記憶/` | 承認済み運用に基づく記憶正本・更新判定 | 正式規程を置かない |
| `削除候補/` | 承認済み削除候補の退避 | DB・原本・規程を無断移動しない |

`チャットDB/` は会話DBの個別作業指示で許可された対象だけを置く。既存の `database/`、`logs/`、`tools/`、`work/`、`作業指示/`、`成果物/`、`.agents/` と外部FChart原本は、この運用による新設・移動・変更の対象外とする。

`ChatGPT/規程案/` は `GitHub連携運用.md` に定める定常受け渡し対象とする。ChatGPTは、承認済みの `nori-sys/fund-team` リポジトリの `origin/main` におけるNori承認済み公開区分・許可パスだけへ、公開可能な未承認案を、個別作業指示を要しない限定的な定常例外として作成・更新できる。送信前に機密情報・個人情報・禁止資産・個別禁止との照合を行い、commit記録に対象パス、公開区分及び照合結果を残す。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。Codexは必要な対象ファイルだけをローカルWorkspaceの同一パスへ限定取得できる。取得前に対象repo・remote・branch・commit・パス、ローカル同名ファイルの有無・ハッシュ・差分を確認し、内容不一致時は上書きせず停止・Nori報告する。Workspace全体の無条件同期又はGitHub版による正式規程の上書きを行わない。`ChatGPT/規程案/` の作成・更新権限を正式規程・ROLE・WORKFLOWの変更権限へ拡張しない。

## ChatGPT/運用/の位置付け

`ChatGPT/運用/` に保存する文書は、ChatGPTが作業案、レビュー、設計文書その他の成果物を作成する際の品質と再現性を安定させるための基準とする。

本領域の文書は、Codex側又はファンドチームの正式規程、ROLE、WORKFLOW又は個別作業指示を置き換えず、それらの責務・権限又は承認状態を変更しない。

本領域の文書が、Noriの最新指示、現行の `AGENTS.md`、承認済み正式規程、ROLE、WORKFLOW又は個別作業指示と競合する場合は、それらを優先し、本領域の文書を根拠に競合を解消、上書き又は拡張してはならない。

未承認の文書案は内容に応じて既存の `ChatGPT/規程案/` 又は `ChatGPT/作業指示案/` に保存し、`ChatGPT/運用/` と混在させない。`ChatGPT/運用/` はGitHubの定常受け渡し又は正式発行物の保存先ではない。GitHubへの送信又は正式文書の発行は、既存の承認済みWORKFLOWとNoriの承認に従う。

## 発行・運用開始の境界

フォルダ作成と運用開始は承認された対象・保存先の範囲だけで行い、会話DB実施は別の個別指示に従う。
