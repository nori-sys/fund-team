## 最新のNori正式判断

Noriは、実装断念を検討するほど停滞していることを踏まえ、
「データの検証精度を下げても仕事を前に進める」
「開発を進めるのに必要な改善を進める」
と明示。

これを受け、Phase 1の完了条件をさらに再設計した。

### 承認済み新方針

中核8セルは次の3状態で扱う。

- accepted：既存証跡だけで一意採用できる
- hold：候補は特定できるが、重複fact、訂正前後、比較系列等の理由で一意採用できない
- rejected：対象外または明確な不一致

8セルすべてをacceptedにすることをPhase 1合格条件としない。

Phase 1は、
- 8セルの候補集合を特定
- concept / context・period / value / unit / 出典の追跡可能範囲を記録
- accepted / hold / rejected の分類規則を決定論的に適用
- hold理由を機械可読で保持
- 同一入力・同一処理版で同じ候補集合・分類結果を再現
- holdをacceptedとして誤採用しない境界を固定
- Phase 2～4でholdを安全に保持・検索・再評価できる要求仕様を作成
- 独立監査で安全に後続Phaseへ渡せると確認

できれば成立とする方向。

## Phase 2～4の新しい考え方

Phase 2：
acceptedとholdを同一モデル内で安全に保持できる最小データモデルを版固定する。

Phase 3：
未確定をholdとして格納し、後から再判定できる運用を候補仕様へ含める。
追加取得失敗・通信失敗・証跡不足も正常な例外ケースとして扱う。

Phase 4：
隔離PoCでacceptedとholdの双方を扱う。
特に、
- acceptedだけを採用系検索で取得
- holdが採用値へ混入しない
- hold理由と候補集合を追跡
- 後から証跡追加時に再評価
- 同一入力で分類結果再現
- 重複候補や訂正前後を誤自動採用しない
を実装・テストする。

実データでacceptedが0件でも、hold処理・検索・再評価・安全隔離の仕組みが成立すればPhase 4実装PoCへ進める方針。
