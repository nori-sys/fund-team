1. Phase 1：横断拡張PoC

`実施 → 検証 → 独立監査 → 要修正時の是正 → 再監査 → 適合`

次Phase移行が承認範囲内なら、Noriの逐次承認を求めず進行する。

Phase 5は、本番採用判断直前までCodex側で進め、最終判断をNoriへ戻す。

## トークンコスト最適化方針

特にPhase 1・4では、大量のXBRL・CSV・JSON・DBレコード等をAIへ逐次全文入力しない。

原則：
- Python、SQL等の決定論的処理で抽出・集約・比較・差分検出・重複判定等を先に行う
- AIには要約、例外、差異、未知パターン、hold候補、判断点を優先入力
- 正常・同型大量事例は代表例＋統計値で扱う
- 再監査は差分・修正点・影響範囲中心
- トークン削減を理由に例外・失敗・hold・未確定事項・安全証跡を省略しない
- 集約処理自体は代表サンプル、境界値、異常系で検証する

目的は、AIを大量データ読解ではなく判断・設計・例外分析へ集中させること。
