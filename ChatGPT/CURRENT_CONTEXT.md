## 重要な調査結果

### 1. kabu.lstとの単純結合は不成立

現行 `kabu.lst` と `kigyo.dat` のコード列の同順一致は先頭2件までで、単純な行番号結合は成立しない。

初期値:
- `kigyo.dat` 先頭4 byte候補値: ユニーク6,099件
- `kabu.lst` 4桁コード: 4,289件、ユニーク4,010件
- 共通部分: 1,864件

先頭4 byteは銘柄コードと確定していない。

### 2. 3DAT共通の先頭キー仮説は否定的

- `kigyo.dat` と他2ファイルで同一行先頭4 byteは14,123件不一致
- `kigyo2.dat` と `kigyo3.dat` は13,079件一致、1,218件不一致
- `kigyo2.dat` 先頭4 byteユニーク14値
- `kigyo3.dat` 先頭4 byteユニーク42値

したがって、先頭4 byteは3ファイル共通の企業キーではない。

### 3. 企業名固定フィールド仮説は否定的

旧仮説の `kigyo.dat` offset 772付近は企業名専用固定長欄とは確認できない。
末尾側にはCP932説明文候補があるが可変位置。
単純抽出では `kabu.lst` の名称と高確度一致規則は得られていない。

### 4. 代表銘柄コード逆引きは不十分

現行 `kigyo.dat` 先頭4 byte候補探索:
- 1001: 1件（行0）
- 1010: 1件（行1）
- 9984: 1件（行8758）
- 7203 / 6506 / 8267 / 2802 / 4755 / 1308: 0件

1001・1010は現行 `kabu.lst` にも存在するが、企業名・業種・既知業績値まで確認できていないため企業同一性は未確定。

### 5. FChart画面値照合は未実施

現在の環境ではFChart起動ウィンドウ・実行ファイルを確認できず、画面表示値からの逆引きは開始できなかった。
売上高・利益・EPS・決算期・発表日とDAT byte領域の対応は未確定。

### 6. 旧→現行追跡の重要訂正

過去途中結果として `kigyo2.dat` 旧10,462件中10,433件完全一致という値があったが、これはレコード境界を要求しないファイル全体バイト列検索だった。

330 byteレコード境界で再検証した正式な補足結果:
- 旧10,462件中、現行に同一330 byteレコードが存在: 8,028件
- 存在しない: 2,434件
- 一致8,028件はすべて現行側に複数候補
- 一意な現行行番号へ追跡できるもの: 0件

したがって、`kigyo2.dat` 完全一致を旧→現行の一意追跡アンカーとして扱う方針は撤回。

既存途中記録は変更せず、境界検証結果を補足証跡として残している。

### 7. 現時点で最も有望な教師データ

旧 `kabu.lst` 先頭の1001 / 1010と旧 `kigyo.dat` 行0 / 行1の先頭4 byte（LE整数）は一致。

さらに旧 `kigyo.dat` で、
- 先頭4 byte値 = 旧 `kabu.lst` コード
- 同一レコード内に銘柄名CP932バイト列あり

の両方を満たす候補が **35件** 見つかった。

ただし、この35件もまだ企業識別規則として一般化していない。
