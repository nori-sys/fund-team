# 20260922-1400_FAND_EDINET・TDnet企業業績データ基盤調査_作業指示書案

> 状態：未承認案・実行禁止

## 01）目的

SOSIA FANDの企業業績データ主系統候補として、EDINETおよびTDnetを調査・比較し、将来の企業業績DBについて、取得元・更新経路・保存方式・正規化方式・利用条件を含む基盤設計案を作成する。

FChart企業業績DATは構造解析・補助検証、IRBankは外部教師・照合用途として一旦位置付けを固定し、本作業では主系統候補をEDINET / TDnet中心に評価する。

本作業は調査・設計PoCであり、正式DBへの大量取込みや本番運用開始を目的としない。

## 02）対象・範囲

### A. EDINET

公式EDINETおよびEDINET APIについて、少なくとも次を確認する。

- API Version 2の利用方法
- 利用登録・APIキー要否
- 書類一覧取得方法
- 書類取得方法
- XBRL / CSV / JSON / PDF等の取得可能形式
- 有価証券報告書・半期報告書等から取得できる財務項目
- 証券コード / EDINETコード / 法人番号等の企業識別方法
- 過去データ取得可能範囲
- 訂正報告書の扱い
- 連結 / 単体、会計基準、決算期の識別方法
- EDINETタクソノミの年度更新への対応
- 自動取得・継続運用の実現性
- 公式利用規約・利用条件

### B. TDnet

JPX公式のTDnetについて、無料閲覧サービスと有料データサービスを分けて確認する。

- 適時開示情報閲覧サービス
- TDnet API
- TDnetサーバ型
- 必要に応じTDnet DBSその他公式サービス

少なくとも次を確認する。

- 決算短信
- 業績予想修正
- 配当予想・配当修正
- XBRL / HTML / PDF等の形式
- 銘柄コード・開示日時等の識別情報
- 取得可能期間
- 更新速度
- 自動取得可否
- 契約・料金・保存・再利用・再配布条件
- SOSIA FAND内部DBへの継続取込みの可否

### C. EDINET / TDnetの役割分担

次の観点で比較する。

- 正確性と原典性
- 更新速度
- 過去データの長さ
- 財務項目の網羅性
- 予想値・修正情報の取得可否
- 企業識別の安定性
- XBRL等の機械可読性
- 自動取得の容易さ
- 訂正・更新履歴の追跡性
- 保存・再利用条件
- コスト
- 長期保守性
- SOSIA FAND既存株価DBとの統合性

一方への全面統一を前提とせず、例えば

- EDINET：確定財務・長期履歴の主系統
- TDnet：決算速報・業績予想修正・配当修正の速報系統

等の役割分担を候補として評価する。

### D. 最小PoC

規程・利用条件上安全に実施可能な場合、少数銘柄を対象として、実データ取得から正規化までの最小PoCを行う。

PoCでは最低限、

- 企業識別
- 決算期
- 売上高
- 営業利益
- 経常利益
- 純利益
- EPS
- 取得元
- 提出 / 開示日時
- 訂正状態

を候補項目とし、取得可能性と正規化難易度を確認する。

認証情報が必要な場合、既存の正規な認証設定がない限り新規設定・表示・共有を行わず、調査段階で停止して必要事項を報告する。
