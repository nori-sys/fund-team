# FAND EDINET取得済みデータ事実固定・0217利用条件検証 作業指示書案

> 状態：未承認案。Noriの正式承認・正式発行前は実行禁止。
> 位置付け：0217とは独立した補助検証工程。0217 v4を改定・置換・遡及修正しない。
> 公開区分案：公開可（原則公開可・禁止情報のみ除外）。実企業・書類ID・実値・取得URL・認証情報・非公開ハッシュ・原記録由来の再識別可能情報等は公開しない。

## 01）目的

0217 v4で取得済みのEDINET固定3書類について、取得前の想定や0217で必要とする結論から逆算せず、取得済みデータから実際に確認できる属性と対応関係を証拠付きで事実固定する。

事実固定完了後、その固定事実だけを入力として0217での利用条件、利用可能範囲及び比較不能条件を設計し、利用開始前にカンの独立監査を受ける。

本作業は「0217で利用できるデータを作る」ことを目的としない。実データと0217の要求が対応しない場合も、その不対応と理由を再現可能に固定できれば正常な成果とする。

## 02）対象・範囲

### Phase 1：取得済み事実の固定

対象は0217 v4に基づき既にtype=1取得済みの固定3書類と、取得時に作成済みの非公開原記録・評価記録・公開安全化成果物に限定する。追加のEDINET接続・取得・再取得は行わない。

各書類について、既存証拠から確認できる範囲で次を固定する。

- 単体／連結
- concept
- context
- period
- entity
- 表示値とXBRL値の対応
- 表示倍率・単位・符号等、表示値とXBRL内部値の対応に必要な属性
- 同値候補の重複有無と、重複する場合に区別できる属性
- 書類間の訂正関係
- 固定8セルとの対応可否
- 対応不能又は一意対応不能の場合の具体的理由
- 各固定事項の証拠位置、確認方法、confirmed/disproved/unavailable の状態

Phase 1では「連結であるはず」「このconcept/contextであるはず」等の期待値を入力条件にしない。0217、IRBANKその他の比較先が要求する属性に合わせて取得済み候補を選び直さない。

既存証拠だけでは確定できない属性は推測せず unavailable と固定する。事実固定のために新たな外部取得、対象拡大又は全文・全fact解析が必要な場合、その属性は未確定として記録し、本作業の対象を拡大しない。

### Phase 2：固定事実に基づく0217利用条件設計

Phase 1の事実固定表とその証拠だけを入力として、固定8セルごとに次を設計する。

- 0217のEDINET入力として利用可能か
- 利用可能とするために一致していなければならない属性
- 利用可能な場合の比較対象・単位・符号・表示精度・訂正系列等の条件
- 利用不能又は一意対応不能とする条件
- 同値候補が存在する場合の識別可否
- IRBANK既判定との意味的比較が成立する条件
- 比較不能を不一致と扱わない条件

Phase 2で新たな事実を作らない。Phase 1の unavailable を「0217で必要だから」という理由で confirmed に変更しない。

Phase 2の利用条件案完成後、Noriが本作業についてカンを独立監査担当として指定していること及び現行監査開始条件を確認し、カンが利用条件を実行前監査する。要修正の場合は承認範囲内でこうが是正し、カンが独立再監査する。適合（承認可）まで反復する。ただしNori判断、対象拡大、新たな取得・権限、正式条件変更又は重大な安全停止が必要な場合は対象部分を停止してNoriへ一括提示する。

カン適合前に、Phase 2の利用条件を0217の実データ判定へ適用しない。

### 対象外

- 0217 v4本文・開始前固定資料・既存監査結果の遡及修正
- 固定3書類以外のEDINET資料
- 654候補全体への展開
- FChart追加解析
- IRBANKの再取得・再調査
- accepted生成、hold解除、rejected復帰
- 本番DB・コード・設定・原本の変更
- 0217の最終比較判定そのもの

## 03）保存先

本作業固有の公開可能成果物は、正式発行後に「指示書・報告書運用」で定まる本作業の作業履歴フォルダへ保存する。

実企業・書類ID・実値・取得URL・非公開ハッシュその他の公開禁止情報を含む事実固定原記録が必要な場合は、既存0217専用非公開子領域を再利用候補とする。新規保存前に、現物の対象・ACL・Git除外・既存0217での承認済み利用範囲を確認する。既存承認範囲で安全に再利用できない場合は書き込まずNori判断へ回す。

既存の0217成果物、開始前固定資料、取得評価、監査記録を上書き・改名・移動しない。

## 04）制約・禁止事項

- EDINETへの追加接続、追加取得、再取得を行わない。
- type=1 ZIP、RAW ZIP、展開全文、一時ファイルを再生成・恒久保存しない。
- type=2 PDFその他の取得方式を使用しない。
- 取得前の想定、数値近似又は比較先の都合から属性を推測しない。
- 既存の「連結」開始前記載を後付けで適合扱いにしない。
- Phase 1の事実をPhase 2の目的に合わせて変更しない。
- 固定8セルとの対応不能を、値の不一致又はデータ誤りと読み替えない。
- accepted生成、hold解除、rejected復帰、654候補展開を行わない。
- 本番DB・コード・設定・原本を変更しない。
- FChart追加読取・解析を行わない。
- IRBANKの新規取得・原本変更・再調査を行わない。
- 非公開情報、認証情報又は第三者権利上公開できない情報をGitHubへ送信しない。

## 06）合格条件・完了条件

### Phase 1合格条件

- 固定3書類について、対象属性が既存証拠から確認できる範囲で証拠付き分類されている。
- 確定不能事項は unavailable とされ、推測で補完されていない。
- 単体／連結、concept、context、period、entity、表示値とXBRL値、重複、訂正関係及び固定8セルとの対応可否が、確認可能範囲で再現可能に記録されている。
- 0217の期待値に合わせた候補選別又は後付け修正がない。
- 比較可能セル数、連結データ件数又は0217利用可能件数の最低値を要求しない。
- 8セルすべて利用不能であっても、その理由が事実固定結果から再現可能ならPhase 1は合格可能とする。

### Phase 2合格条件

- 利用条件のすべてがPhase 1の固定事実又は現行0217の正式要求へ明示的に追跡できる。
- Phase 1で unavailable の事項を推測で confirmed としていない。
- 利用可能、利用不能、一意対応不能を再現可能に区別できる。
- 比較不能を数値不一致として扱わない。
- Phase 2利用条件のカン実行前独立監査が「適合（承認可）」である。

### 本作業完了条件

Phase 1及びPhase 2の成果物・自己検証・必須独立監査が完了し、A又はBの未解決リスク及び未充足の明示条件が残っていないこと。

本作業の完了は、0217 v4の完了、固定8セルの比較成立、EDINETとIRBANKの一致、accepted生成、hold解除、1332全体完了又は本番採用を意味しない。

カン適合後も、本作業で確定した利用条件を0217へ実際に適用して判定を再開することは本作業の対象外とし、0217側の現行正式条件及び必要な承認を別途確認する。

公開可（原則公開可・禁止情報のみ除外）。

ただし、GitHub連携運用に定める公開禁止情報、実企業・書類識別子・実値・取得URL・認証情報・非公開ハッシュ、既存非公開原記録の内容、第三者の権利又は契約上公開できない情報及び再識別可能な小集計はGitHubへ送信しない。

禁止情報を除外しても意味・証拠性・正確性を維持できる成果物だけを公開する。安全に除外できない成果物は公開不可とする。

## 08）通常運用からの例外

1. 本作業は0217とは独立した補助検証工程であり、0217 v4を改定・置換しない。
2. Phase 1は通常の会社情報DB構築工程としてこうが自己検証するが、Phase 2の利用条件は0217実データ判定へ使用する前にカンの独立監査を必須とする。
3. カンの監査対象はPhase 2利用条件及びPhase 1固定事実との追跡整合であり、取得済み事実を目的に合わせて再設計・是正することではない。
4. 本作業の正式発行だけでは追加取得、0217判定再開又は上位判定変更を承認しない。
