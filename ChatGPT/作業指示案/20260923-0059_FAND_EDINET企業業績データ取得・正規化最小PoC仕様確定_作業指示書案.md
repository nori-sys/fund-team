# FAND EDINET企業業績データ取得・正規化最小PoC仕様確定 作業指示書案

> 状態：未承認・実行禁止

## 01）目的

SOSIA FANDの企業業績データ主系統候補であるEDINETについて、実装PoCへ進むために必要な取得・解析・正規化仕様、安全境界および検証条件を確定する。

本作業では本番DBへの投入や正式実装は行わず、後続の隔離PoCを安全かつ再現可能に実施できる仕様を作成する。

## 02）対象・範囲

対象：

- EDINET API Version 2
- EDINETコード等の企業識別情報
- EDINET XBRLおよび関連メタデータ
- 有価証券報告書等の企業業績取得候補書類
- 訂正書類と元書類の関係
- 企業業績データの正規化候補
- 隔離PoCの対象・件数・検証方法

仕様確定対象：

- API認証・APIキーの取扱方針
- PoC対象銘柄
- 対象書類種別
- 取得件数・対象期間
- RAWデータの定義と保存方針
- XBRL解析対象
- 抽出対象業績指標
- 企業識別規則
- 会計期間、連結／単体、会計基準、通貨、単位の取扱い
- 訂正・差替えの処理規則
- PoC用データ領域・DB構成
- 検証方法および合格条件

対象外：

- `database/fund_stock.db` への変更
- FChart株価DBとの物理結合
- TDnet APIの契約・利用
- 本番運用コードの実装
- APIの正式採用
- 自動更新運用
- 大量取得
- 外部公開サービスへのデータ配信

## 03）保存先

本作業の成果物は、正式発行後に対応する作業履歴フォルダへ保存する。

既定配置先を持つ正式資産は変更しない。

## 04）制約・禁止事項

本作業は仕様確定を目的とし、原則として実データ取得PoCそのものは行わない。

EDINET APIキーについては、

- 既存キーの探索
- 認証情報の表示
- 認証情報のGitHub保存
- 第三者への共有

を行わない。

新規APIキー取得または既存APIキーの利用が必要な場合は、その必要性、取得方法、保存方法、安全対策を整理し、Noriの判断事項として提示する。

以下は実施しない。

- 本番DB変更
- 正式API設定変更
- FChart原本変更
- 本番コード変更
- 契約・課金
- 大量・継続的なAPIアクセス
- 認証情報を成果物・ログ・GitHubへ記録すること

仕様調査上、公式資料だけでは判断できない事項は推測で確定しない。

## 05）成果物

少なくとも以下を作成する。

1. `EDINET最小PoC仕様案.md`
2. `EDINET企業業績項目定義案.md`
3. `EDINET書類・訂正処理規則案.md`
4. `EDINET企業識別規則案.md`
5. `EDINET最小PoC実施条件・未決事項.md`
6. 作業報告書

`EDINET企業業績項目定義案.md` では、少なくとも以下を候補として検討する。

- 売上高
- 営業利益
- 経常利益
- 税引前利益
- 当期純利益
- 親会社株主に帰属する当期純利益
- EPS
- 総資産
- 純資産
- 営業キャッシュフロー

各項目について、XBRL conceptだけでなく、期間、連結範囲、単位、会計基準等の文脈を保持する設計とする。

## 06）合格条件・完了条件

以下を満たすこと。

- EDINET API利用に必要な認証条件が明確
- PoC対象銘柄・書類・期間・取得件数が限定されている
- RAWの定義と保存可否が明確
- 抽出対象項目と正規化方法が定義されている
- 企業識別規則が定義されている
- 連結／単体、期間、単位、会計基準を区別できる
- 訂正書類を元データの上書き・削除ではなく履歴として扱える
- 不明データを誤って正規化しない隔離条件が定義されている
- PoC用領域が本番DBから分離されている
- APIキー等の認証情報を成果物・GitHubへ保存しない設計となっている
- 後続作業として最小PoCを実施可能か、停止すべきかを判断できる
- 独立監査で適合（承認可）となっている

仕様だけでは判断不能な事項が残る場合は、未決事項として明示し、無理に完了扱いしない。

## 07）公開区分

公開可（原則公開可・禁止情報のみ除外）。

ただし以下は公開禁止とする。

- APIキー
- 認証情報
- セッション情報
- 個人情報
- 第三者原文
- ダウンロードしたEDINET原文データ
- 公開条件を確認できないデータ
- その他、正式WORKFLOWで公開禁止とされる情報

禁止情報を除外しても内容の正確性・証拠性を維持できない成果物は公開しない。
