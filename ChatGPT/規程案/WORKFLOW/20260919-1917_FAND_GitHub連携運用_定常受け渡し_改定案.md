# GitHub連携運用 定常受け渡し 改定案

## 目的

GitHubをChatGPTとCodexの限定受け渡し層として定常利用し、反復する安全条件を個別作業指示から規程へ移す。

## 定常操作

### ChatGPTからGitHub

ChatGPTは、公開可能な未承認案を ChatGPT/作業指示案/ と ChatGPT/規程案/ へ作成・更新できる。承認済みスレッド引継ぎ運用に基づく CURRENT_CONTEXT.md と HANDOVER/ も従来どおり対象とする。GitHub上の存在だけで正式承認・正式発行・送達・受領・実行開始を意味しない。

### GitHubからCodex Workspace

Codexは、作業に必要な ChatGPT/作業指示案/ 又は ChatGPT/規程案/ の対象ファイルだけをGitHub mainから正規Workspaceの同一パスへ限定取得できる。対象repo・branch・commit・ファイルを確認し、Workspace全体のgit pull、merge、rebase、reset、stashを同期手段として使用せず、既存未コミット・未追跡資産へ干渉しない。安全に限定取得できない場合は停止する。

### CodexからGitHubからChatGPT

Codexは作業完了又は監査完了後、成果物/作業履歴/＜原正式作業指示書の基底名＞/ に保存された公開可能な作業報告書、独立監査結果、検証結果及び当該作業固有成果物をGitHub上の同一パスへ反映できる。正式配置先を持つ資産は作業履歴へ複製して送信しない。

## 公開禁止対象

認証情報、個人情報、顧客・取引先その他の機密情報、FChart原本、大容量株価データ、database/fund_stock.db、バックアップDB、ログ原本、公開可否不明資産及び個別に外部共有禁止とされた資産は定常操作対象外とする。疑義がある場合は送信せず停止する。

## Git安全条件

書込み前に対象repo、remote、branch、remote最新状態、先行・遅延・分岐、対象ファイル、stage対象、公開安全性及び既存未コミット・未追跡資産への非干渉を確認する。対象変更だけを安全に分離できる場合は最新origin/mainを基点とする一時worktree等を利用できる。

Workspace全体の安易なpull、merge、rebase、reset、stash、force push、remote変更、恒久Git設定変更及び認証方式変更は定常処理に含めない。安全な分離又はfast-forward反映ができない場合は停止する。

## 原報告

定常GitHub書込み後は、根拠、branch、commit ID、送信ファイル、公開安全性確認、既存資産への非干渉確認、検証結果及び未解決事項を原報告へ記録する。

## 個別作業指示との関係

個別作業指示は上記定常運用を毎回再記載しない。GitHubへ反映しない、特定成果物を除外する、通常と異なる保存先を使う、より厳しい公開条件を課す等の例外だけを記載する。

## 承認前の扱い

本書は未承認案であり、独立監査及びNoriの正式承認前に正式GitHub連携運用.mdへ反映しない。
