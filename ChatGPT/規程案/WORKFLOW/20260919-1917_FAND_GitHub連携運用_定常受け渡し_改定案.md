# GitHub連携運用 定常受け渡し 改定案

## 目的

GitHubをChatGPTとCodexの限定受け渡し層として定常利用し、反復する安全条件を個別作業指示から規程へ移す。

## 定常操作

### ChatGPTからGitHub

ChatGPTは、承認済みの `nori-sys/fund-team` リポジトリの `origin/main` における `ChatGPT/作業指示案/` 又は `ChatGPT/規程案/` のNori承認済み公開区分・許可パスに限り、公開可能な未承認案を作成・更新できる。公開可の確定者はNori、又はNoriが承認した公開区分分類を適用する担当者とする。送信前に機密情報・個人情報・禁止資産・個別禁止との照合を行い、commit記録に対象パス、公開区分及び照合結果を残す。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。承認済みスレッド引継ぎ運用に基づく CURRENT_CONTEXT.md と HANDOVER/ も従来どおり対象とする。GitHub上の存在だけで正式承認・正式発行・送達・受領・実行開始を意味しない。

### GitHubからCodex Workspace

Codexは、作業に必要な ChatGPT/作業指示案/ 又は ChatGPT/規程案/ の対象ファイルだけを、承認済みの `nori-sys/fund-team` リポジトリの `origin/main` から正規Workspaceの同一パスへ限定取得できる。対象repo・remote・branch・commit・ファイルとローカルの同名ファイルの有無・ハッシュ・差分を確認し、ローカルに同名ファイルがあり内容不一致の場合は上書き・取得をせずNoriへ報告する。新規作成又はNoriが明示した置換だけを許可し、Workspace全体のgit pull、merge、rebase、reset、stashを同期手段として使用せず、既存未コミット・未追跡資産へ干渉しない。安全に限定取得できない場合は停止する。

### CodexからGitHubからChatGPT

Codexは、目的、対象、保存先、禁止事項、成果物、完了条件及びNori承認済みの公開区分を定める個別作業指示に基づく作業の完了又は監査完了後、成果物/作業履歴/＜原正式作業指示書の基底名＞/ に保存された `公開可` の作業報告書、独立監査結果、検証結果及び当該作業固有成果物だけを、承認済みの `nori-sys/fund-team` リポジトリの `origin/main` 上の同一パスへ反映できる。担当AIは各送信で公開区分、機密情報・個人情報・禁止資産・個別禁止との照合結果を原報告へ記録する。正式配置先を持つ資産は作業履歴へ複製して送信しない。

## 公開禁止対象

認証情報、個人情報、顧客・取引先その他の機密情報、FChart原本、大容量株価データ、database/fund_stock.db、バックアップDB、ログ原本、公開可否不明資産及び個別に外部共有禁止とされた資産は定常操作対象外とする。疑義がある場合は送信せず停止する。

## Git安全条件

書込み前に対象repo、remote、branch、remote最新状態、先行・遅延・分岐、対象ファイル、stage対象、公開安全性及び既存未コミット・未追跡資産への非干渉を確認する。定常手順では正規Workspaceの外にある一時worktreeを利用しない。Noriが対象worktreeを明示承認した個別例外では、worktree内で正本又は保全対象を更新せず、対象変更だけを安全に分離できる場合に限る。

Workspace全体の安易なpull、merge、rebase、reset、stash、force push、remote変更、恒久Git設定変更及び認証方式変更は定常処理に含めない。安全な分離又はfast-forward反映ができない場合は停止する。

## 原報告

定常GitHub書込み後は、根拠、branch、commit ID、送信ファイル、公開安全性確認、既存資産への非干渉確認、検証結果及び未解決事項を原報告へ記録する。

## 個別作業指示との関係

ChatGPTによるGitHub上の参照又はレビューは、送達、受領、承認、実行開始又は作業全体の完了を意味しない。

個別作業指示は、目的、対象、保存先、禁止事項、成果物、完了条件及び公開区分を必ず記載する。上記定常運用のGit安全手順は毎回再記載しないが、GitHubへ反映しない、特定成果物を除外する、通常と異なる保存先を使う、より厳しい公開条件を課す等の例外は記載する。
