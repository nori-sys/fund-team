# GitHub連携運用.md 正式文書更新後のミラー同期完遂_修正案

状態：未承認案  
対象：`規程/WORKFLOW/GitHub連携運用.md`  
目的：正式規程・ROLE・WORKFLOW等の更新後、GitHub参照用ミラー同期までを一連の定常処理として明確化する。

## 修正案1：「規程ミラー更新」を改定

### 規程ミラー更新

1. ローカル正本の正式発行又は正式更新後、公開禁止情報を含まない対象文書はGitHub参照用ミラーの更新対象とする。
2. 正式文書の更新と参照用ミラー同期は、別途Noriの個別指示を必要としない一連の定常処理として扱う。
3. Codexは、正式文書の更新完了後、対象文書について公開安全性、対象パス、ローカル正本との内容一致及びGitHub書込み条件を確認し、本運用の定常書込み手順に従ってGitHub参照用ミラーへ反映する。
4. ミラー反映後、対象パス、commit ID、GitHub上の対象blobとローカル正本の内容一致を確認する。
5. 正式文書更新後にミラー同期を未実施のまま作業完了としてはならない。ただし、公開禁止、競合、認証要求、remote先端変化、規程矛盾その他の停止条件に該当する場合は同期を停止し、その理由と必要な判断を報告する。
6. 不一致時は修正、pull、merge、上書き、reset、rebaseその他の自動修復を行わず停止し、差分と影響を報告する。

## 修正案2：「基本フロー」へ補足

正式規程、ROLE、WORKFLOW、入口文書等のローカル正本を正式更新した場合、当該更新に伴うGitHub参照用ミラー同期は、正式更新作業から派生する定常後続処理として扱う。

Codexは、Noriから「GitHubへ同期せよ」という追加指示を待たず、本運用に定める公開条件、安全条件及びGitHub書込み条件を満たす場合は同期まで継続する。

## 修正案3：「監査と記録」へ追加

正式文書更新を伴う作業の完了報告には、次を含める。

- 更新したローカル正式正本
- 正式承認又は正式更新の根拠
- GitHubミラー同期の実施結果
- GitHub commit ID
- ローカル正本とGitHub上の内容一致確認結果
- 同期未実施の場合は、その停止条件及び必要なNori判断
