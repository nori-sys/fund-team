# GitHub連携運用.md 正式文書の標準公開区分_修正案

状態：未承認案  
対象：`規程/WORKFLOW/GitHub連携運用.md`

## 目的

正式規程、ROLE、WORKFLOW及び入口文書の正式発行・正式更新後、公開可否について毎回Noriの追加承認を要求せず、公開安全性を満たす文書はGitHub参照用ミラーへ定常同期できるようにする。

本修正は、正式文書のGitHub正本化、公開範囲の無制限な拡張又は公開禁止情報の送信を許可するものではない。

## 修正案1：「公開区分の基本原則」へ追加

正式文書については、次を標準公開区分とする。

1. `AGENTS.md`、`START_HERE.md`、`規程/ROLE/`、`規程/WORKFLOW/` に正式発行又は正式更新された文書は、公開禁止情報、第三者権利上公開できない情報又はNoriが個別に公開不可と指定した情報を含まない限り、GitHub参照用ミラーへの公開を標準で許可されたものとして扱う。
2. 前項の対象文書について、正式発行又は正式更新の都度、GitHub公開可の個別承認を追加で要求しない。
3. 公開可否の判断は、正式文書であることだけを根拠に無条件で行わず、送信前に公開禁止情報、個別禁止、第三者権利及び公開安全性を確認する。
4. 公開安全性に合理的な疑義がある場合、又は公開禁止情報を安全に除外できない場合は同期を停止し、Nori判断を求める。
5. 本規定は、GitHubを正式文書の正本に変更せず、ローカルWorkspaceの正式文書を正本とする既存原則を維持する。

## 修正案2：「GitHub操作の承認経路／書込み」へ補足

承認後の正式文書の参照用ミラーについては、本運用の「正式文書の標準公開区分」をGitHub書込みの承認根拠として扱う。

対象が標準公開区分に該当し、公開安全性及び本運用の定常書込み条件を満たす場合、正式発行又は正式更新後のミラー同期についてNoriの追加のGitHub書込み指示を必要としない。

ただし、高リスク操作、公開禁止情報、対象外パス、正本性の不一致又は本運用の停止条件に該当する場合は、この標準公開区分を根拠として処理を継続してはならない。

## 修正案3：「規程ミラー更新」を改定

### 規程ミラー更新

1. ローカル正本の正式発行又は正式更新後、標準公開区分に該当し、公開禁止情報を含まない対象文書はGitHub参照用ミラーの更新対象とする。
2. 正式文書の更新と参照用ミラー同期は、別途Noriの個別指示を必要としない一連の定常処理として扱う。
3. Codexは、正式文書の更新完了後、対象パス、正式承認又は正式更新の根拠、公開安全性、ローカル正本との内容一致及びGitHub書込み条件を確認し、本運用の定常書込み手順に従ってGitHub参照用ミラーへ反映する。
4. ミラー反映後、対象パス、commit ID、GitHub上の対象blobとローカル正本の内容一致を確認する。
5. 標準公開区分に該当する正式文書について、GitHub公開可の個別承認がないことだけを理由に同期を停止してはならない。
6. 公開禁止、競合、認証要求、remote先端変化、正本性不一致、規程矛盾その他の停止条件に該当する場合は同期を停止し、その理由、影響及び必要なNori判断を報告する。
7. 不一致時は修正、pull、merge、上書き、reset、rebaseその他の自動修復を行わず停止する。

## 修正案4：「監査と記録」へ補足

正式文書のミラー同期を行った場合、原報告には少なくとも次を記録する。

- 対象正式文書
- 正式承認又は正式更新の根拠
- 標準公開区分への該当確認
- 公開禁止情報・個別禁止・第三者権利との照合結果
- GitHub commit ID
- ローカル正本とGitHub参照用ミラーの内容一致確認結果
- 既存未コミット変更及び未追跡資産への非干渉確認
- 未解決事項

## 想定する完了フロー

正式承認
→ ローカル正本の正式更新
→ 標準公開区分・公開安全性確認
→ GitHub参照用ミラー同期
→ 内容一致確認
→ 完了報告

追加のNori判断は、公開禁止、個別禁止、権限不足、高リスク操作、正本性不一致その他の停止条件が存在する場合に限る。
