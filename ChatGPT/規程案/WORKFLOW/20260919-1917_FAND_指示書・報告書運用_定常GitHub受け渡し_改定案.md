# 指示書・報告書運用 定常GitHub受け渡し 改定案

## 目的

作業指示から作業報告、監査、ChatGPTレビューまでの標準フローへGitHub受け渡しを組み込み、個別作業指示への定型条件の反復記載を不要にする。

## 作業指示案の標準フロー

ChatGPT → GitHubのChatGPT/作業指示案/ → 対象ファイル限定取得 → ローカルChatGPT/作業指示案/ → Nori正式承認・発行 → 作業指示/ → Codex実行。

GitHub上の作業指示案は未承認・未発行であり、Codexの実行根拠とはしない。

## 作業報告の標準フロー

Codex実行 → 成果物/作業履歴/＜指示書基底名＞/ → 作業報告書・独立監査結果・作業固有成果物 → 個別作業指示でNoriが `公開可` とした対象だけをGitHubへ反映 → 必要な場合のChatGPT参照・レビュー → Nori確認・完了承認。

作業報告書及び独立監査結果は、目的、対象、保存先、禁止事項、成果物、完了条件及び公開区分を定めるNori承認済み個別作業指示に含まれる `公開可` の対象だけを、GitHub連携運用の定常手順で反映できる。ChatGPTのGitHub参照・レビューは送達、受領、承認、実行開始又は作業全体の完了を意味しない。

## 個別作業指示へ毎回記載しない事項

作業報告書の作成場所、命名規則、公開可能な報告書・監査結果のGitHub同一パス反映、公開安全性確認、stage確認、既存資産混入防止、non-fast-forward時の安全分離又は停止、force push禁止、remote・Git設定・認証方式の無断変更禁止、commit ID等の原報告記録は承認済みWORKFLOWに従う通常動作とする。

## 個別作業指示に記載する事項

目的、対象、保存先、制約・禁止事項、成果物、合格条件・完了条件及び公開区分を必ず記載する。承認済み定常運用の具体的なGit安全手順は重複記載を要しない。GitHub定常運用を停止又は変更したい場合は、その例外を明記する。

## 既定配置先を持つ成果物

正式DB、正式コード、正式設定、正式規程、ROLE、WORKFLOWその他の既定配置先を持つ資産は作業履歴へ重複コピーしてGitHubへ送信しない。

## 承認前の扱い

本書は未承認案であり、独立監査及びNoriの正式承認前に正式指示書・報告書運用.mdへ反映しない。
