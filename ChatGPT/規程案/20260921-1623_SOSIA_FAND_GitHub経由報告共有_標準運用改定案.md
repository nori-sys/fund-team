# SOSIA FAND GitHub経由報告共有 標準運用改定案

## 01）目的

ChatGPTとCodexの間で、Noriを不要な中継者とせず、作業指示・途中報告・監査結果・成果物確認をGitHub経由で直接共有できる標準運用へ改定する。

対象は主に次の正式WORKFLOWである。

- `規程/WORKFLOW/指示書・報告書運用.md`
- `規程/WORKFLOW/GitHub連携運用.md`

## 02）改定方針

### A. 作業報告書の随時共有を標準化する

Codexは、承認済み個別作業指示に基づいて作成した作業報告書について、作業完了・監査完了を待たず、以下を満たす場合はGitHubへ随時反映できる。

- 個別作業指示の公開区分が `公開可`
- 対象が作業履歴内の作業報告書、独立監査結果、検証結果、公開可能な作業固有成果物である
- 機密情報、個人情報、認証情報、FChart原本、DB本体、ログ原本、大容量データその他の禁止対象を含まない
- 既存未commit変更や別作業資産を混入しない
- GitHub連携運用の安全条件を満たす

### B. 完了前共有を正式に認める

GitHubへの途中報告反映は、次を意味しない。

- 作業完了
- 監査完了
- Nori承認
- 正式成果物の受領
- 実装・分析結果の確定

途中報告は、ChatGPT・Codex・Nori間のレビュー、壁打ち、方向修正、設計改善のための共有情報として扱う。

### C. ChatGPTが途中報告を直接参照できる状態を標準とする

ChatGPTは、GitHubへ反映された公開可能な作業報告書、独立監査結果、検証結果、作業固有成果物を直接参照し、次を行える。

- Codex実行結果の評価
- Noriとの壁打ち
- 次段階の設計改善
- 作業指示案の改善
- 不整合、抜け、運用リスクの発見

これにより、Noriへローカル報告書のコピー・貼付けを原則として要求しない。

### D. 長期・自走作業では途中報告のGitHub反映を標準とする

長期間継続する調査、分析、実装、検証等では、主要な調査区切り又は判断材料が得られた時点で作業報告書を作成し、公開可能ならGitHubへ反映する。

最終統合報告書とは別に、途中報告を連番で保持してよい。

### E. 禁止対象は従来どおり維持する

次はGitHubへ送信しない。

- FChart原本
- 正式DB、バックアップDB
- ログ原本
- 認証情報
- 個人情報、顧客情報、機密情報
- 公開可否が不明な資産
- 正式コード、正式設定、正式規程、ROLE、WORKFLOWの無断複製
- その他現行規程で禁止された対象

## 03）標準フロー

```text
ChatGPT
  ↓ 作業指示案
GitHub
  ↓
Codex
  ↓ 実行
作業報告書・途中報告
  ↓ 公開可なら随時反映
GitHub
  ↓
ChatGPT
  ↓ 評価・壁打ち・改善
Nori
  ↓ 必要な判断のみ
ChatGPT / Codex
```

Noriは、正式承認、方針変更、権限拡大、安全停止、重要資産変更その他の人間判断が必要な事項だけを担当する。

## 04）改定対象

### `指示書・報告書運用.md`

主に以下を改定する。

- 07）作業報告書
- 09）基本フロー
- 10）GitHub連携

「作業完了または監査完了後」に限定している読み方を排除し、公開可能な途中報告の随時GitHub反映を標準化する。

### `GitHub連携運用.md`

主に以下を改定する。

- GitHub操作の承認経路
- 定常書込み対象
- Codex → GitHub → ChatGPT
- 作業指示・成果物の扱い
- 基本フロー

作業完了前でも、承認済み作業の公開可能な途中報告を定常書込み対象とする。

## 05）設計原則

SOSIA FANDでは、今後次を標準原則とする。

> GitHub等でAI間の直接受け渡しが可能な情報について、Noriを不要なコピー・貼付け・中継作業に使用しない。

Noriは最終意思決定者であり、AI間の通常情報搬送担当ではない。

## 06）改定後に期待する状態

- ChatGPTがCodexの実行結果を直接確認できる
- Codexの途中結果をChatGPTが早期に評価できる
- 長期作業でも方向ずれを早期検出できる
- Noriのコピー・貼付け作業が減る
- ChatGPT→Codex→ChatGPTの改善循環が成立する
- 正式承認や高リスク判断だけをNoriへ集約できる

## 07）状態

本書は未承認の改定案である。

正式WORKFLOWの変更は、独立監査とNoriの正式承認後に行う。
