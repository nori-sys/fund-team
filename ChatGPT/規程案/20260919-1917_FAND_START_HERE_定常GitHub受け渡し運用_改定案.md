# START_HERE.md 定常GitHub受け渡し運用 改定案

## 目的

入口文書からGitHub定常運用の根拠と参照先を明確にし、個別作業指示への定型条件の重複記載を減らす。

## 改定要旨

プロジェクト固有の定義へ「指示書・報告書運用」と「GitHub定常受け渡し」を追加する。

GitHub上の情報の読取り・確認・書込みは、Noriの直接指示、承認済みGitHub連携運用その他のWORKFLOWに定める定常運用、又はNori承認済み個別作業指示を根拠として実施できるものとする。定常書込みは、目的、対象、保存先、禁止事項、成果物、完了条件及びNori承認済みの公開区分を定める個別作業指示の付随処理に限る。

定常運用の対象、保存先、公開条件、禁止事項、確認条件及び停止条件は各WORKFLOWに従う。公開可否が不明、未分類又は個別禁止の場合は送信せずNori判断を待つ。通常運用から外れる場合は、個別作業指示で例外を指定する。

GitHubからローカルへの受信は、対象repo・branch・commit・パスを確認した対象ファイルの新規作成だけを定常処理とする。ローカルに同名ファイルがある場合は、内容ハッシュと差分を確認し、不一致なら上書き・取得をせずNoriへ報告する。Noriが明示した置換以外は、Workspace全体の無条件なgit pull、merge、rebase、reset又は上書き同期を定常処理としない。

作業の目的、対象又は権限そのものが不明確な場合は、定常運用を根拠に作業範囲を拡張せず停止する。

## 承認前の扱い

本書は未承認案であり、独立監査及びNoriの正式承認前に正式START_HERE.mdへ反映しない。
