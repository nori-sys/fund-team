# AGENTS.md 定常GitHub受け渡し運用 改定案

## 目的

通常のGitHub受け渡しを承認済みWORKFLOWへ集約し、個別作業指示への定型条件の反復記載を減らす。

## 改定要旨

現行の「GitHub書込みはNori承認済み個別作業指示の範囲だけ」という条件を、次へ改定する。

GitHubの読取り・確認・書込みは、(1) Noriの明示的な直接指示、(2) 承認済みGitHub連携運用その他のWORKFLOWに定める定常運用、(3) Nori承認済み個別作業指示、のいずれかを根拠として実施できる。定常書込みは、Nori承認済み個別作業指示が目的、対象、保存先、禁止事項、成果物、完了条件及び公開区分を定める作業の付随処理に限定する。

定常運用の対象、保存先、公開条件、禁止事項、確認条件及び停止条件は承認済みWORKFLOWで限定する。公開区分は個別作業指示でNoriが `公開可` と明示した対象だけとし、担当AIは機密情報・個人情報・禁止資産・個別禁止との照合結果を原報告へ記録する。公開可否に疑義、未分類又は個別禁止がある場合は送信せずNori判断を待つ。定常運用を任意のGitHub書込み、正式規程・ROLE・コード・DB・設定その他の重要資産の変更権限へ拡張しない。

個別作業指示には、目的、対象、保存先、禁止事項、成果物、完了条件及び公開区分を必ず記載する。承認済み定常運用の具体的なGit安全手順は重複記載を要しないが、通常運用からの例外は明記する。

GitHub上の規程コピーはローカル正本を置き換えず、無条件な上書き・同期・承認状態の推測を行わない。

## 高リスク操作

remote変更、恒久Git設定変更、認証方式・credential・token・API key・SSH keyの設定又は共有、force push、共有履歴改変、branch protection・ruleset変更、Public/Private変更、新規リポジトリ作成・削除、機密情報・個人情報・重要資産の外部共有、規程・ROLE・重要資産のGitHub正本化は定常運用に含めず、従来どおりNoriの明示承認を必要とする。

## 承認前の扱い

本書は未承認案であり、独立監査及びNoriの正式承認前に正式AGENTS.mdへ反映しない。
