## 4. 新たに判明した運用課題

現行 `規程/WORKFLOW/GitHub連携運用.md` では、正規Workspace外の一時worktree利用は原則禁止で、Noriが明示承認した個別例外としてのみ認めている。

このため、ローカル分岐や未コミット変更があるたびに、Noriが同じworktree許可指示をCodexへ入力する必要がある。

Noriはこの反復入力を手間と感じている。

## 5. 次工程の方針

個別指示で毎回回避するのではなく、`GitHub連携運用.md` を最小改定し、一定条件下の隔離worktreeを **標準安全手順** として扱えるようにする案を検討する。

候補条件：
- 正規Workspaceに未コミット変更、未追跡資産、branch分岐等がある
- 個別作業指示で公開区分が確定済み
- GitHub送信対象を明確に限定できる
- 最新 `origin/main` 起点の隔離worktreeを使用
- 対象ファイルだけをcommit
- push直前に親commitと最新 `origin/main` の一致を確認
- fast-forward pushのみ許可
- force push / reset / rebase / remote変更 / Git設定変更 / 認証変更は禁止
- non-fast-forward、競合、対象分離不能、公開安全性疑義がある場合のみ停止してNoriへ上げる
- 正規Workspaceの既存未コミット変更・未追跡資産へ触れない
