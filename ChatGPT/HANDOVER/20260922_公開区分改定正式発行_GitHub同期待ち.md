# SOSIA FAND ChatGPT スレッド引き継ぎ

作成日: 2026-09-22

## 最優先テーマ

公開区分運用の正式改定を反映したうえで、ChatGPT ↔ GitHub ↔ Codex の直接報告運用を実際に機能させ、FChart自走調査を前進させる。

## 1. 公開区分運用の改定

対象正式WORKFLOW:
- `規程/WORKFLOW/GitHub連携運用.md`
- `規程/WORKFLOW/指示書・報告書運用.md`

経緯:
1. FChart自走調査の報告書4件が `公開不可` とされ、ChatGPTがGitHub経由で直接参照できなかった。
2. 原因を確認したところ、現行運用が安全側に寄りすぎ、FChart関連という理由で報告書全体を一括非公開にしやすい問題が判明。
3. 「原則公開可・禁止情報のみ除外」へ改定する方針を決定。
4. ChatGPTが改定案を `ChatGPT/規程案/` へGitHub出力。
5. Codexが監査・修正し、カンの第3回独立再監査で **適合（承認可）**。
6. Nori承認後、Codexがローカル正式WORKFLOWへ正式発行。
7. 反映後の独立監査も **適合（承認可）**。

確定内容:
- 個別作業指示に `公開可（原則公開可・禁止情報のみ除外）` を明記。
- 公開区分が未記載・不明確なら送信しない。
- 公開安全性確認済みの作業履歴内成果物は随時GitHub参照用ミラーへ反映可能。
- FChart原本、正式・バックアップDB、ログ原本、認証情報、個人情報、機密情報、第三者権利上の禁止情報は除外。
- 派生資料も禁止資産を実質的に再現・露出しないことを確認。
- ChatGPTはGitHubから直接参照できるが、GitHub内容のみで承認・実施・送達・受領・完了・重要資産変更を認定しない。
- ローカル正本性、Nori承認権限、Git安全条件、AI通信の正本性は維持。

## 2. 現在の未完了作業

正式WORKFLOW 2文書のGitHub参照用ミラー同期はまだ完了報告を受領していない。

Codexへは以下の同期指示を提示済み:
- 正規Workspace、Gitルート、remote、branch、origin/main最新状態確認
- ローカル正式2文書とGitHub側との差分確認
- 対象2文書だけを通常commit・push
- GitHub main上で存在・内容一致を確認
- 既存未コミット変更・未追跡資産へ非干渉
- force push / reset / rebase / stash / remote変更 / Git設定変更 / 認証方式変更禁止

次スレッドでは、まずこの同期完了報告の有無を確認する。

## 3. FChart自走調査

調査対象:
`成果物/作業履歴/20260921-1452_FAND_FChart未解決事項解明_自走調査/`

既存報告:
- `01_調査設計・初動報告.md`
- `02_構造調査・一次報告.md`
- `03_取込仕様調査・検証報告.md`
- `04_未解決事項・継続調査報告.md`

旧公開区分では4件とも公開不可だった。
新しい正式WORKFLOW適用後は、今後の個別作業指示で公開区分を新基準に合わせることで、公開安全性確認済み成果物をGitHubへ反映し、ChatGPTが直接レビューする運用へ移行する。

## 4. 「出力してください」の意味

Noriの明示方針:
本プロジェクトでは今後、**「出力してください」＝原則GitHub所定領域へ直接出力**とする。

ダウンロード用ファイルだけを作る運用は標準としない。

規程案:
`ChatGPT/規程案/`

作業指示案:
`ChatGPT/作業指示案/`

スレッド引き継ぎ:
`ChatGPT/CURRENT_CONTEXT.md`
`ChatGPT/HANDOVER/`

## 5. 次に行うこと

1. 正式WORKFLOW 2文書のGitHub同期完了報告を確認。
2. GitHub上の正式ミラー内容を確認。
3. 必要ならFChart自走調査の現行作業指示・公開区分を新基準へ整合。
4. 公開可能な途中報告・成果物をGitHub経由で直接参照。
5. 調査結果を評価し、未解決事項の優先順位と次段階を設計。

## 6. 運用原則

- Noriを不要な情報搬送役にしない。
- ChatGPTは設計・評価・改善に集中する。
- Codexは正式規程・正式作業指示の範囲で実作業を自走する。
- 正式承認、権限拡大、重要資産変更、安全停止等はNoriへ上げる。
- 未実施を実施済みと扱わない。
- GitHubは参照用ミラーであり、ローカル正本・承認・送達・受領を代替しない。
