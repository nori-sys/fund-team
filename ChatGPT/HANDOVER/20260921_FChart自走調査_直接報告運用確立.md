許可:
- 全域列挙
- 内容読み取り
- テキスト・設定・ログ・バイナリの非破壊解析

- 新規関連候補の自律選定
- 調査順序・優先順位・解析方法のCodex側自律決定

- 原本コピー
- 実行

## 2. 調査進捗

確認済み:
- FChart更新機構は、タイムスタンプ比較→ダウンロード→解凍・コピー→銘柄リスト自動リンク→設定登録という設計。
- 2世代の `kigyo.lzh` は `kigyo.dat`、`kigyo2.dat`、`kigyo3.dat`、`zaimu.dat` を格納。
- 現行 `kabu.lst` と `Userkabu.ini` は4,289件のコード・名称が全件一致。
- 原本メタデータは調査開始前後で一致。
- 既存35件教師データ構造観測を現行原本へ再基準化。
- `kigyo.dat`: 14,297件 × 823 bytes。
- `kigyo2.dat` / `kigyo3.dat`: 各14,297件 × 330 bytes。
- 現行ハッシュは既存構造観測時点と一致。
- 55 byte反復候補、YYMM候補、名称位置非固定の既存観測は現行原本にも適用可能。

未確定:

- 企業の一意対応
- 項目名
- 単位・倍率
- `Zaimu.dat` 構造

統合報告・最終独立監査は未了。Codex調査継続中。

## 3. 途中報告の直接共有問題と解決

問題:
Codexの作業報告書がローカルにしか存在しない場合、ChatGPTは本文を読めず、実行結果の壁打ちができなかった。

Nori判断:
SOSIA FAND全体の標準運用として、ChatGPT ↔ GitHub ↔ Codex の直接循環を強化し、Noriの手作業を極力減らす。

正式改定済み:
- `規程/WORKFLOW/指示書・報告書運用.md`
- `規程/WORKFLOW/GitHub連携運用.md`

独立監査:
適合（承認可）

GitHub参照用ミラー:
commit `c2699f16a531a9dd07cc64cdc995fe4169d67e55`

新標準:
- `公開可` の途中作業報告書・独立監査結果・検証結果・公開可能な作業固有成果物は、完了前でもCodexがGitHubへ随時反映できる。
- ChatGPTはGitHubから直接参照できる。
- GitHub反映は完了・承認・正式受領を意味しない。
- Noriは通常の情報搬送担当にならない。
- 高リスク判断・正式承認等だけNoriへ上げる。

## 5. 運用原則

- Noriを不要なコピー・貼付け・AI間中継者にしない。

- Codexは正式規程・正式作業指示の範囲で実作業を自走する。
- 正式承認や権限拡張はNoriへ上げる。
- 未実施を実施済みと扱わない。
- GitHubは参照用ミラーであり、正本・承認者ではない。
