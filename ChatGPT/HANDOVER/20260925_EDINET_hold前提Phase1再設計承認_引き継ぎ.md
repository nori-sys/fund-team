## 3. 承認済み新Phase 1設計

8セルすべてをacceptedにすることをPhase 1合格条件から外す。

各セル・候補を次の3状態で扱う。

- accepted：既存証跡だけで一意採用できる
- hold：候補は特定できるが一意採用できない
- rejected：対象外または明確な不一致

Phase 1は次を満たせば成立可能とする。

1. 8セルの候補集合を特定
2. concept / context・period / value / unit / 出典の追跡可能範囲を記録
3. accepted / hold / rejected の分類規則を決定論的に適用
4. hold理由を機械可読で保持
5. 同一入力・同一処理版で同じ候補集合・分類結果を再現
6. holdをacceptedへ誤採用しない境界を固定
7. Phase 2～4でholdを安全に保持・検索・再評価できる要求仕様を作成
8. 独立監査で安全に後続Phaseへ渡せると確認

## 4. 実装優先方針

未確定データを理由に実装を停止しない。

Phase 2：
accepted / hold を同一モデル内で安全に保持できる最小データモデルを設計。

Phase 3：
holdの格納・再判定、追加取得失敗・通信失敗・証跡不足を通常の例外ケースとして扱う運用を設計。

Phase 4：
隔離PoCでaccepted / holdの双方を扱い、
- holdが採用値へ混入しない
- hold理由と候補集合を追跡できる
- 証跡追加時に再評価できる
- 同一入力で分類結果が再現する
- 重複・訂正前後を誤自動採用しない
ことを実装・検証する。

acceptedが0件でも、holdを安全に扱う仕組みが成立すればPhase 4実装PoCを行える設計へ変更する。

## 5. 追加取得

追加取得は打ち切る方針。
